# Qt 文本排版测量模型（实测，误差 0）

写这份是因为分页连续错过三轮，最后是**用户实测反馈"内容缺了一段"**才挖到底：
先用**绝对坐标**判断（一段一页）、再用 `line.height()` 累加（每页多塞 2~3 行、底部被裁）、
最后发现"用整篇文档的行坐标推算页面"本身就不成立。
下面的数字都是离屏打印每一行/每一块坐标量出来的，不是推测。

## 一、行步进 ≠ line.height()

段落格式用 `setLineHeight(line_height * 100, ProportionalHeight)`（默认 190%）。
实测（正文 19pt、双页每栏 608px）：

| 量 | 值 | 说明 |
| --- | --- | --- |
| `QTextLine.height()` | 29 | **只是文字本身的高度** |
| 相邻行 `y` 之差（真实步进） | **51** | 实际值 |
| `height() × 行距倍数`（模型值） | 55 | 比真实值**偏大 ~7%** |
| 章首标题（+4pt 加粗） | height 37 → 步进 ~70 | = 37 × 1.9 |

**规则**：
- 中间行 → 用**相邻行的 `y` 差**（最准）；
- 块内**最后一行** → 用**模型值** `height() × 行距倍数`（偏保守，宁可少放一行）；
- **图片行 → 直接返回 `line.height()`，绝不乘行距倍数**（见下）；
- **绝对不要**用"块占位反推"（`block_span - line.y()`）：`blockBoundingRect` 在比例行距下
  不含行距，而文档末尾那块还会用到**可能过期的** `document.size()`，反推值偏小
  → 一页多塞一两行 → 底部被裁。

```python
def line_advance(block_layout, i, is_image=False):
    line = block_layout.lineAt(i)
    if is_image:                                              # 图片：就是图片高度
        return line.height()
    if i + 1 < block_layout.lineCount():
        return block_layout.lineAt(i + 1).y() - line.y()       # 中间行：实测
    return line.height() * self._line_height                    # 末行：模型（保守）
```

## 一之二、插图那一行会被比例行距放大（用户实测："图标不在左栏""下半截总是空的"）

段落格式是 `setLineHeight(190, ProportionalHeight)`，而图片那"一行"的
`line.height()` 就是图片高度（实测 600px）。**Qt 会把比例行距同样套在图片行上**：

| 量 | 值 |
| --- | --- |
| 图片高度 | 600 |
| 该行步进（未特殊处理） | **1140** = 600 × 1.9 |
| 图片下方凭空多出的空白 | **540px** |
| 后果 | 分页以为这块高 1140 → 图片被挤到单独一页（双页模式落到**右栏**） |

**修法**（两处必须一起改，否则"量的"和"画的"又不一致）：
1. 插图段落的块格式：`image_block.setLineHeight(100, QTextBlockFormat.SingleHeight)`；
2. `_line_advance(..., is_image=True)` 直接返回 `line.height()`。

自检样本里的插图要**够大**（400×300 起）：4×4 的小图看不出这个空白，
断言会形同虚设（反向对照：旧行为下间隙 282px vs 修后 12px）。

## 二、分页必须"渲染后量它自己"

**不要**用整篇文档的行坐标推算每一页：整篇里排的是**完整段落**，页面上是**段落片段**
（续页片段不带首行缩进 → 断行位置不同），图片块的真实高度也只有渲染出来才知道。
实测个别页因此多塞 103px（约 2 行）→ 底部被裁。

现在的做法（`ReaderView._paginate`）：

```
for 每一页:
    按上一页的字数外推一个"足够宽"的候选区间（2 倍量）
    _render_fragments(view, fragments_of(候选区间), heading_first=True)   # 与真实翻页同一入口
    在**这个渲染结果**上逐块逐行量：
        行底 = blockBoundingRect(block).top() + line.y() + line_advance(...)
        行底 - documentMargin > 可用高度 → 停，上一行末尾就是本页终点
    把页内偏移映射回**全章偏移**：para_starts[段落号] + 片段起点 + 行内偏移
```

代价：一章一次分页 ~0.24s（19 页规模），只在换章 / 改设置 / 改窗口（防抖 160ms）时跑。

### 踩过的三个坑
1. **`block.layout()` 是空的**：Qt 布局按需进行，必须先调 `layout.blockBoundingRect(block)`
   触发它，再去读 `lineCount()`。顺序反了什么都量不到 → 每页只前进一个字
   （实测一章被分成 **2898 页**）。
2. **坐标系混用**：页面文档里 `block.position()` 是**页内坐标**，
   而 `_page_offsets` 要的是**全章字符偏移**，必须按片段映射回去。
3. **`heading_first` 要一致**：页面渲染时每页都传 `True`（内部条件 `start == 0` 才生效），
   分页候选渲染也必须传 `True`，否则首块按正文字体量、实际按大字号画 → 溢出。

## 三、块占位与文档高度（只作参考，别用来算页高）

- `layout.blockBoundingRect(block).height()` = `(n-1) × 步进 + 末行 height`，
  **比真实占位少一个 (步进 − height)**——不能直接当块高用。
- `document.size().height()` 在比例行距下同样不准，而且**可能滞后一帧**；
  它只能当"辅助信号"，不能当判据。
- 正文用 `document().setDocumentMargin(26)` 控制内边距（**不是 CSS padding**）。

## 四、滚动条会把宽度"粘住"（用户可见的内容丢失）

翻页模式**必须** `ScrollBarAlwaysOff`。早先做"某页比视口高就打开滚动条"的兜底：

```
某页稍溢出 → 滚动条打开 → viewport 从 608 缩到 598 → 文字重排成更多行
→ 溢出更多 → 滚动条一直开着（粘住）；而分页是按 608 算的 → 底部文字被裁
```

现象就是"**有时顺、有时像丢了一段内容**"。现在的自检会断言
"翻页模式视口宽度恒定" + "不显示滚动条"。

## 五、分页锚点

- **最后一页的起点不能等于整章长度**：`offsets.append(min(page_end, total))` 会在
  `page_end == total` 时追加"总长"本身，最后一页区间成了 `[total, total)` = **空白页**
  （用户实测："有些章节最后一页是空白的"）。正确做法是 `page_end >= total` 时直接
  `break`（本页已到章末，不该再加页起点）。
- 主锚点是 **字符偏移 `char_offset`**（整章显示文本的偏移），跨字号、跨单双页、
  跨窗口尺寸都稳定；`block_index` / `page_index` 只作兼容。
- 一章的第一段是**章首标题**（`set_content` 里 prepend），所以段落序号整体后移一位；
  `ChapterContent.images` 的键也要跟着 +1。
- 内嵌插图的段落内容固定是**一个** `U+FFFC`（对象替换字符），
  分页/进度用的字符偏移完全不受影响；插图有高度上限（`IMAGE_MAX_HEIGHT_RATIO = 0.62`）。
- `_page_offsets` 存每页起始字符偏移；一页 = 一个字符区间 → 切成
  `(段落号, 起, 止)` 片段；**续页片段不带首行缩进**（`continuation` 块格式）。

## 六、滚轮翻页：按"格"累计

机械滚轮/触摸板常把**一次滚动拆成多个小事件**（-60+-60、-30×4），
按事件翻页就会一次跳好几屏——**中间整段内容直接看不到**（用户实测反馈）。
必须累计到一格（`WHEEL_NOTCH = 120`）才翻**一屏**，并用 `WHEEL_COOLDOWN = 0.12s`
抑制同一格的连发事件。

## 七、自检写法

- **权威判据是像素**：抓 `view.viewport()` 的图，从底部往上找第一行"有 ≥4 个非背景像素"的
  行，要求 `height - 该行 >= 6`。
  - 必须抓**稳定帧**（连续两次 `grab()` 内容一致），否则会抓到上一帧 → 误报"贴底"。
  - 不要用 `document().size().height() <= viewport + 2` 当判据：分页和自检若用同一个
    模型就是**循环验证**，会一直是绿的（这个错误真实发生过）。
- 反向对照很重要：把旧公式临时装回去，确认断言**真的会红**，否则它可能什么都没验。
- 内容完整性：逐屏走一遍，把每屏文字拼起来（去空白）与原文比较，必须一字不差。
- **先跑 `--quick` 再跑 `--ui`**；`--ui` 联网，真实章节偶尔只有 272 字，
  分页类断言要用**内容量确定的合成正文**（见 `scripts/harness.py` 的 `synthetic_chapter()`）。
