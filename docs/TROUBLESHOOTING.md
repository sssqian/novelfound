# 开发过程问题记录（踩坑与解决）

本文记录本次开发（含环境搭建、抓取解析、界面、打包四个阶段）中**实际出现过并已解决**的
问题，供你复现/排查时参考。每条都按「现象 → 原因 → 解决」写，最后附一份经验清单
和需要手动清理的文件列表。

> 环境前提：本次开发跑在 **DSH 沙箱（文件策略 workspace-write）** 下，
> 只能写工作区目录。下面标注「沙箱限制」的问题**在你自己的普通桌面环境里不会出现**，
> 但代码里的防御性处理仍然保留，属于有益的健壮性改进。

## 1. 环境与依赖

### 1.1 pip 装不上依赖（Permission denied）
- **现象**：`pip install PyQt5 requests beautifulsoup4 lxml` 报
  `ERROR: Could not install packages due to an OSError: [Errno 13] Permission denied:
  ...\pip-unpack-xxxx\requests-2.34.2-py3-none-any.whl.metadata`
- **原因**：沙箱限制（不是包的问题）。pip 解包时要在临时目录里创建 `.whl.metadata`，
  该写入被拒绝；把 `TEMP/TMP` 指到工作区后依旧被拒（同一策略）。
- **解决**：绕过 pip，写了临时脚本 `_pyi_fetch.py`（已删除）——
  查 PyPI JSON API 挑兼容 wheel → 用 `urllib` 下载 → `zipfile` 解压到
  `.venv\Lib\site-packages`。PyQt5 等全部装成功。
- **你的环境**：直接 `pip install -r requirements.txt` 即可，无需这套绕行。

### 1.2 创建虚拟环境失败
- **现象**：`python -m venv .venv` 报
  `Error: Command '[...python.exe, '-m', 'ensurepip', ...]' returned non-zero exit status 1`
- **原因**：`ensurepip` 同样需要写临时目录，被沙箱拒绝。
- **解决**：`python -m venv --without-pip .venv` 建环境，再用 1.1 的方式把 pip 的 wheel
  解压进去；验证 `python -m pip --version` 正常。
- **你的环境**：`python -m venv .venv` 正常可用。

### 1.3 自写下载器选错了依赖版本
- **现象**：装完后 `import requests` 报 `ModuleNotFoundError: No module named 'cgi'`
  （Python 3.13 已删除 `cgi` 模块）。
- **原因**：版本排序用字符串比较，`"2.9.2" > "2.34.2"` 成立 → 选中了 2016 年的 requests 2.9.2；
  同时 ABI 标签匹配过宽，把 `cp311` 的 wheel 也当成兼容。
- **解决**：改成「数字元组比较 + 跳过预发布版 + 严格匹配 `cp313/abi3/py3-none-any`
  与 `win_amd64`」，并优先原生 `cp313` 轮子。

### 1.4 PowerShell / curl 无法访问网络
- **现象**：`Invoke-WebRequest` 报「基础连接已经关闭」，
  `curl` 报 `schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS`。
- **原因**：Windows schannel 在当前环境下拿不到 TLS 凭证，**不是沙箱、也不是网络不通**。
- **解决**：改用 Python 的 `urllib`/`requests` 做探测与抓取（实测 200 正常）。

### 1.5 控制台中文乱码 / UnicodeEncodeError
- **现象**：调研脚本打印中文变成 `������`；`print` 直接抛
  `UnicodeEncodeError: 'gbk' codec can't encode character ...`。
- **原因**：中文 Windows 控制台默认代码页 GBK，而脚本输出 UTF-8。
- **解决**：运行时设 `PYTHONIOENCODING=utf-8`，脚本内 `sys.stdout.reconfigure(encoding="utf-8")`，
  并把结果**写文件**而不是只打印。

### 1.6 数据目录不可写导致启动失败
- **现象**：`AppConfig()` 抛 `PermissionError: [WinError 5] 拒绝访问:
  'C:\Users\Shao\AppData\Roaming\NovelFound'`。
- **原因**：沙箱不允许写 `%APPDATA%`。
- **解决**：`config.data_dir()` 增加两级容错——
  ① 支持环境变量 `NOVELFOUND_HOME` 覆盖（顺带成为「绿色版/便携模式」功能）；
  ② 目标目录不可写时自动回退到系统临时目录，保证程序仍能启动。

## 2. 抓取与解析

### 2.1 中文关键词没做 URL 编码
- **现象**：探测脚本抛 `UnicodeEncodeError: 'ascii' codec can't encode characters`。
- **原因**：拼 URL 时直接塞了中文关键词。
- **解决**：统一用 `urllib.parse.quote(keyword, encoding=...)`。

### 2.2 候选站点大面积失效
- **现象**：手工列的 20 多个「笔趣阁」域名，多数 403 / SSL 失败 / 已改版。
- **解决**：从开源「阅读」App 的书源 JSON 里收割 **440 个候选域名**批量探测，
  最终筛出 3 个稳定可用源（和图书、蚂蚁文学、笔趣阁5200）并写入内置规则表。
  这也是「多书源 + 可自定义书源」设计的由来。

### 2.3 广告过滤误删正文容器（最隐蔽的一个）
- **现象**：某章正文显示成「我的书架 / 玄幻小说 / 排行榜…」等导航文字。
- **原因**：广告容器判定里有个宽松规则——只要 class/id 里含 `ad` 就删。
  而正文外层容器叫 **`content_read`**，结尾正好是 `ad`（re**ad**），
  于是整块正文被当作广告删掉，程序只能退而取全页最大节点（导航区）。
- **解决**：改成三层判定——
  ① `AD_TOKEN_RE` 按**词边界**匹配（`-ad`/`ad_`/`ads`…），`content_read` 不再命中；
  ② 广告 id 用专门正则 `AD_ID_RE`（`ad`/`adt1`/`cbad`/`ctad`/`cstad` 等）；
  ③ 增加 `SAFE_CONTAINER_RE` 白名单（content / read / list / dir…）永不当广告删。

### 2.4 正文容器"谁文本多选谁"选错
- **现象**：短章节里抓到的正文是导航+推荐位。
- **原因**：`pick_content_node` 原先在**所有候选选择器**里挑文本量最大的节点。
  外层 `div.content_read` 把导航、推荐一起算进去（445 字），
  反而比真正的 `#content`（319 字）更长。
- **解决**：改为**按选择器优先级**判断：先看规则里配的 `#content`，
  文本量达标就用它；全都不达标才退到第一个命中的选择器；最后才用全页最大块兜底。

### 2.5 目录顺序错乱（最新章节跑到最前面）
- **现象**：点开目录，第一条是「第二百三十六章 大结局」。
- **原因**：经典模板的目录里既有「《书名》最新章节」预览块，又有「正文」块；
  而蚂蚁文学把这两块塞进**同一个 `<dl>`**，靠 `<dt>` 分隔。
  整块跳过 → 目录全空；整块保留 → 预览块（倒序）排在前面。
- **解决**：目录解析改为**按 `<dt>` 分段**：优先取「正文」段；
  再按 URL **保留最后一次出现的位置**去重（自动剔除预览重复项）；
  最后用章节号统计升降比例，整体倒序时自动翻转。

### 2.6 搜索关键词编码与页面编码不是一回事
- **现象**：笔趣阁5200 搜索返回首页，没有结果。
- **原因**：该站页面是 GBK，但搜索 URL 里的关键词必须用 **UTF-8** 编码；
  我最初把「页面编码」直接复用成了「关键词编码」（GBK），站点解析不出来。
- **解决**：拆成两个字段——`encoding`（响应解码）与 `search_encoding`（关键词编码，默认 UTF-8）。

### 2.7 防盗版标记与文本节点碎片
- **现象**：正文里混进「和-图-书」；一句话被拆成两段。
- **原因**：和图书在正文里插入 `<acronym>`/`<samp>` 标记；删除这些标签后，
  BeautifulSoup 留下**相邻文本节点**，`get_text("\n")` 会在它们之间插入换行。
- **解决**：`DROP_TAGS` 增加 `acronym/samp/tt/kbd/var/cite`；
  `strip_noise()` 末尾调用 `soup.smooth()` 合并相邻文本节点。

### 2.8 带标签的字段抓成了整行
- **现象**：详情页分类显示成「作者： 唐家三少」。
- **原因**：`.book_info div` 命中第一个 div（作者行）；而经典模板是「作　　者：xxx」（含全角空格）。
- **解决**：新增 `label_fields` 规则（`{"category": ["类型"], "status": ["状态"]}`），
  按标签定位冒号后的值，且标签内部允许空白（`作\s*者`）。

### 2.9 SSL 证书过期
- **现象**：`SSLCertVerificationError: certificate has expired`。
- **解决**：`HttpSession` 捕获 `SSLError` 后自动降级 `verify=False` 重试一次，
  并屏蔽重复告警（在日志中留痕）。

### 2.10 抓错页面时不能把导航当正文
- **现象**：极端情况下（404 页、验证页）会返回一堆导航文字当"正文"。
- **解决**：加两道闸——正文总字数 `< 20` 直接抛错；
  `looks_like_nav()` 判定"短文本 + 大量导航词"时抛 `ParseError`，
  界面显示「抓到的内容疑似导航/推荐页而非正文，请切换书源或重试」。

## 3. 界面与阅读器

### 3.1 调字号没反应
- **现象**：点 A+/A− 只改了配置，正文没变。
- **原因**：`render(paragraphs=None)` 里有一句「没传段落就 return」，而字号变化时正是没传。
- **解决**：`render()` 缺参时使用内部保存的 `self._paragraphs` 重绘。

### 3.2 换主题后"黑字黑底"
- **现象**：切到夜间主题，背景变暗但文字仍是黑色，几乎看不清。
- **原因**：文字颜色写在 `QTextCharFormat` 里（而不是 CSS），只换样式表不重绘字符格式。
- **解决**：主题切换后强制 `render()` 重绘；设置对话框保存后同样重绘。

### 3.3 滚动位置丢失（三个原因叠加）
- **现象 A**：切章再切回来，回到章首。原因：`set_loading()` 清空视图时把
  `_scroll_pos` 重置为 0，而"记住位置"发生在清空之后。
  → 解决：新增 `remember_position()`，在清空视图**之前**记录。
- **现象 B**：即使记下了位置，恢复后仍在顶部。原因：`setHtml` 后文档尚未完成布局，
  滚动条最大值是 0，`setValue(600)` 被钳制为 0。
  → 解决：`_restore_scroll()` 轮询等待（每 40ms 一次，最多 12 次）直到能容纳目标位置。
- **现象 C**：跳章后回到上一章，位置还是丢。原因：进度表一本书只存一条记录，
  新章节的进度覆盖了旧章节的。
  → 解决：阅读器内维护「章节 URL → 滚动位置」的会话内映射，切章前先存旧章位置。

### 3.4 没加入书架的书不记进度
- **现象**：只是随手读一章，下次打开要重新找章节。
- **解决**：`Library` 增加 `history` 分支，未加入书架的书也记录阅读历史与进度；
  书架页底部增加「最近阅读」区块。

### 3.5 自检脚本误报（不是产品 bug）
- **现象**：断言"字号已应用"失败，但界面其实是对的。
- **原因**：`QTextBlock.charFormat()` 在首块会返回默认格式（黑色、无字号），
  而真实字符格式在文本位置上。
- **解决**：改用 `QTextCursor` 定位到第 1 个字符再读 `charFormat()`。

## 4. 启动与打包

### 4.1 run.bat 在 cmd 里解析失败（已修复）
- **现象**：双击 `run.bat` 输出
  `'�环境并安装依赖' is not recognized as an internal or external command`，
  并且明明 `.venv` 存在却走了"创建虚拟环境"分支，最后报"创建虚拟环境失败"。
- **原因**：我用 **UTF-8 编码 + LF 换行** 保存了批处理文件。
  `cmd.exe` 按当前代码页（中文 Windows 为 GBK）逐行解析，且对 LF 换行的多行
  `if (...)` 块处理异常，导致整段逻辑错乱。
- **解决**：重写为 **ASCII 编码 + CRLF 换行**（实测：49 个 CRLF、0 个裸 LF、
  最大字节值 126），并把中文说明移到 README。现在双击可正常跳过安装直接启动。
- **经验**：`.bat` 永远不要用 UTF-8/无 BOM 保存；跨语言用 ASCII 最稳。

### 4.2 窗口标题重复
- **现象**：标题栏显示「小说搜索阅读器 v1.0.0 - 小说搜索阅读器」。
- **原因**：同时设置了 `setApplicationDisplayName()` 与 `setWindowTitle()`，Qt 会拼接。
- **解决**：去掉 `setApplicationDisplayName`，标题固定为「小说搜索阅读器 v1.0.0」。

### 4.3 单文件 exe 秒退（改为 onedir）
- **现象**：`dist/NovelFound.exe` 启动后 1 秒内进程消失，无任何输出。
- **定位**：用最小 `hello world` 样例做对照实验——**同样失败**，报
  `[PYI-xxxx:ERROR] Could not create temporary directory!`；
  加 `--runtime-tmpdir` 后变成
  `Failed to extract VCRUNTIME140.dll: failed to open target file! fopen: Permission denied`。
  → 证明是环境对"运行时解包到临时目录"的限制，**与应用、与 spec 无关**。
- **解决**：`build/novelfound.spec` 默认改为 **onedir** 模式（不打解包、直接运行），
  实测 2 秒内出窗口；单文件模式保留为开关
  `NOVELFOUND_ONEFILE=1 pyinstaller ...`，并在 README 里注明其前置条件。
- **你的环境**：普通桌面通常两种模式都能用；onedir 启动更快、也更容易过安全软件。

### 4.4 PyInstaller 装不上
- **原因**：同 1.1（pip 写临时目录被拒）。
- **解决**：复用 wheel 直装方式，装了 pyinstaller 6.22.2 +
  pyinstaller-hooks-contrib / altgraph / pefile / pywin32-ctypes / packaging / setuptools。
- **你的环境**：`pip install pyinstaller` 即可；当前 `.venv` 里已经装好，可直接重新打包。

## 4.5 `tempfile.mkstemp` 在受限环境下会卡死（新增）

- **现象**：单元测试跑到 `SourceStats` 那组时**整个进程挂住**，没有任何输出、也不报错；
  单独验证发现 `tempfile.mkstemp(dir=<系统临时目录>)` 调用后不返回。
- **原因**：与 1.1 同源——受限环境对系统临时目录的新建文件操作会阻塞（pip 早期
  「下载超时 120 秒」其实也是这个原因，而不是网速慢）。
- **解决**：新增 `novelfound/storage.py`，用「同目录 + 固定后缀 + 进程号」的临时文件
  配合 `os.replace` 实现原子写入，替换掉 config / library / source_stats 里的
  `mkstemp`；测试的临时目录也改到工作区内（`tests/.tmp/`）。
- **影响面**：普通环境无差别（`mkstemp` 本身没问题），但这一改动让持久化更少依赖
  环境特性，属于净收益。

## 5. 我（助手）的操作失误

### 5.1 误杀了你正在运行的 Anki ⚠️
- **经过**：验证 `run.bat` 时用 `Get-Process pythonw | Stop-Process -Force` 清理测试进程，
  而 Anki 也以 `pythonw.exe` 运行，被一并强制结束。
- **原因**：按**进程名**批量筛选，范围过大。
- **正确做法**：按 PID、命令行或窗口标题精确定位后再结束；
  后续所有验证我都改为「记录启动前后的 PID 差集 + 匹配窗口标题」。
- **影响**：Anki 会持续写盘，强制结束一般只可能丢失最后几秒操作；
  若提示"数据库未正常关闭"，按提示让它自动检查即可。

### 5.2 命令挂起 120 秒
- **经过**：`cmd /c run.bat | Out-Null` 一直不返回，直到超时。
- **原因**：`run.bat` 用 `start` 启动的 GUI 进程**继承了管道句柄**，
  PowerShell 等到管道关闭才算结束。
- **解决**：改用 `Start-Process -PassThru` 拿 PID，不用管道。

### 5.3 PowerShell 单引号里的 `\n` 不是换行
- **经过**：`Set-Content -Value 'import sys\nprint(...)'` 写出的 Python 文件里
  是字面量 `\n`，PyInstaller 打包时直接 `SyntaxError`。
- **解决**：用 here-string 或 `-join "`r`n"` 显式拼 CRLF 再写文件。

## 6. 经验清单

1. **外部站点抓取要假设"随时会变"**：选择器全失效时必须有启发式兜底 + 中文报错，
   而不是白屏或乱码；多源冗余比单源死磕更实用。
2. **广告过滤宁可用白名单保护正文容器**：任何"含 ad 就删"的规则都会误伤
   `content_read` 这类名字。
3. **取文本块不能只按长度**：外层容器永远更长，要按选择器优先级。
4. **目录要按 `<dt>` 分段 + 去重保尾 + 自动翻转**，否则"最新章节"预览块会污染顺序。
5. **颜色/字号写在字符格式里**：改主题或字号后必须重绘文档。
6. **滚动位置恢复要等布局完成**，并区分"同一章重绘"和"换章"。
7. **`.bat` 用 ASCII + CRLF**；中文说明放文档里。
8. **批量结束进程前先按 PID/命令行确认**，不要只按进程名。
9. **打包失败先用 hello world 对照实验**，能立刻区分"环境问题"和"应用问题"。
10. **给打包产物留一条自检通道**（本项目的 `--selftest`），
    windowed exe 没有控制台时，靠退出码 + 报告文件才能确认它真的能联网抓书。

## 8. 本轮新增功能中的问题（首行缩进 / 书源导入）

### 8.1 首行缩进必须按字体度量计算
- **坑**：直接写死 `setTextIndent(40)` 这类像素值，用户放大字号后缩进会显得过小。
- **做法**：用 `QFontMetrics(font).horizontalAdvance("汉") × 缩进字符数`，
  字号/字体一变缩进同步变；并且**不要**往正文里插全角空格（会污染复制与字数统计）。

### 8.2 Legado 书源的 `searchUrl` 选项段解析
- **坑**：形如 `/s.php,{"method":"POST","body":"s={{key}}"}`，用
  `partition(",{")` 切分后选项段**已经丢掉了开头的 `{`**，直接 `json.loads` 会失败，
  结果被当成 GET 请求。
- **做法**：按需补回 `{` 再解析；同时放宽校验——关键词可以出现在 URL 里，
  也可以只出现在 POST 表单里。

### 8.3 导入对话框里的模态弹窗
- **坑**：导入成功后弹 `QMessageBox`，自动化脚本会被永久阻塞（真实用户也要多点一次）。
- **做法**：改成在对话框内的状态标签里显示结果，不打断操作；
  弹窗只保留给"必须用户确认"的场景。

### 8.4 选择器字段要保留兜底链
- **坑**：从 Legado 转换时只取源里的一个选择器，站点小改版就全废。
- **做法**：转换后的字段是「源里的选择器 + 内置兜底选择器」的列表，
  解析器按顺序尝试，命中即用（这也是内置书源一直很稳的原因）。

### 8.5 探测新书源（方案 B）实现中的两个坑
- **重复请求**：如果"每个搜索写法 × 每套模板"都各自抓一次页面，最坏要几百次请求。
  → 改成**每个搜索写法只抓一次**，拿这份 HTML 本地比对所有模板
  （用一个 `_CachedHttp` 把预取页面喂给 `RuleSource`，不改解析器）。
- **URL 合法性校验太松**：`urlparse("https://这不是网址")` 也能得到 netloc，
  导致"输入了中文"这种明显错误被当成正常域名去请求。
  → 加校验：主机名必须匹配 `[A-Za-z0-9.-]+` 且含至少一个点。

### 8.6 测试里的"首页前缀"陷阱
- **坑**：测试用的假 HTTP 按 URL 片段匹配页面，而 `https://site.com/` 是**所有**
  该站 URL 的前缀，于是所有请求都返回了首页，测试假阳性/假阴性。
- **做法**：假 HTTP 改成按「路径 + 查询串」匹配（首页只在 path 为 `/` 时返回），
  这样 `?searchkey=`、`/book/27/index.html` 各走各的。

### 8.7 网络找书源（方案 C）踩的三个坑
- **搜索引擎大面积不可用**：实测百度/360/搜狗/DDG/Startpage/Yandex 全被反爬或需要 JS，
  只有 Bing（cn.bing.com / www.bing.com）能返回可解析的 HTML。
  → 引擎做成可扩展清单，默认只留 Bing；失败时明确提示而不是静默无结果。
- **搜索词决定成败**：`"书名 小说 在线阅读"` 出来的几乎全是起点/云起/百科等官方站
  （8 个候选里 6 个要过滤），而 `"书名 笔趣阁"` 直接给出 7 个可用聚合站。
  → 改成三个搜索词合并去重（笔趣阁 / 免费小说 / 在线阅读），并给"标题含笔趣阁"
  的候选加分。
- **"能搜到"不等于"搜索有效"**：有的站搜索接口失效，任何关键词都返回同一批书，
  探测（搜索→目录→正文）会**全部通过**，存下来却是个假书源。
  → 探测第 2 关增加**关键词相关性校验**：搜索结果里必须出现与目标书名匹配的条目，
  否则判定"搜索接口已失效"。这一条同时修好了方案 B 的误判。
- **站点自己的搜索表单最靠谱**：有的站搜索参数是 `?key=`、表单无 action（提交到当前页），
  硬编码的写法覆盖不到。
  → 探测时先解析首页 `<form>`（action + method + 文本输入框 name）生成搜索写法，
  优先尝试，再退回通用清单。

## 9. 线上崩溃复盘：点「网络找书源 → 开始查找」程序直接消失

这是本项目最严重的一个 bug（用户实际遇到），记录完整排查过程。

### 现象
在「网络找书源」对话框里填好书名、点「开始查找」，**程序窗口瞬间消失**，
没有任何提示（打包后的 exe 是 `console=False`，什么都看不到）。

### 定位过程
1. **先怀疑输入**：用离屏 + 真实窗口跑了 3 种输入、4 种操作时序、8 种奇怪输入，
   全部正常 → 说明不是输入问题。
2. **翻 Windows 事件日志**（关键一步）：

   ```
   故障应用程序名: NovelFound.exe
   故障模块名称:   Qt5Core.dll 5.15.2.0
   异常代码:       0xc0000409
   异常数据:       0000000000000007
   ```
   `0xc0000409` + 子码 `7` = `FAST_FAIL_FATAL_APP_EXIT`，即 `abort()`；
   故障模块是 Qt5Core.dll（`qFatal()` 所在库）——这正是
   **"PyQt 槽函数里抛出未捕获 Python 异常"** 的典型签名：
   PyQt5 打印 traceback 后调用 `qFatal()` → `abort()` → 进程消失。
3. **从用户处拿到关键信息**："是在网络找书源里点开始查找崩的"，
   而我的自检脚本只调用了对话框的内部方法、**没点按钮**，所以完全没覆盖到。
4. 直接点按钮复现，抛出：

   ```
   AttributeError: 'str' object has no attribute 'base_url'
     File ".../ui/source_discover_dialog.py", line 121, in on_start
       existing = [s.base_url for s in self._existing_hosts()]
   ```

### 根因
`_existing_hosts()` 返回的是**域名字符串列表**（`["www.hetushu.com", ...]`），
而 `on_start()` 里却按对象取 `s.base_url`。异常发生在 Qt 的 `clicked` 槽里，
于是走 `qFatal()` → 整个进程被 abort。

### 修复
1. 一行修正：`existing = self._existing_hosts()`；
2. 新增 `novelfound/errors.py`：
   - `install_crash_handler()`：`sys.excepthook` + `threading.excepthook` 把 traceback
     写入数据目录的 `crash.log`，并用 `faulthandler` 覆盖原生崩溃；
   - `guard_slot` 装饰器：给按钮槽套一层保护，出错时**记日志 + 界面提示**而不是崩掉
     （已用于导入/探测/发现/订阅等入口按钮）；
   - 注意：PyQt 会把 `clicked(bool)` 的参数传进槽，装饰器必须按原函数签名裁剪参数，
     否则会 `TypeError`（这个坑当场踩到并修掉了）。
3. 把内部进度标记 `__elapsed__` 改成独立信号 `elapsed(float)`，
   不再混进对话框日志。

### 教训
- **测试要点按钮，不要只调内部方法**：这次自检覆盖了"结果处理"，漏掉了"点击入口"，
  于是最常被用户触发的路径反而没有回归测试。现在 `tests/verify_ui.py` 会真的
  `button.click()` 跑一遍导入/探测/发现三条路径。
- **窗口化程序必须有崩溃日志**：没有 `crash.log` 时，这类崩溃对用户就是"程序没了"。
- **Windows 事件日志 + WER 报告是定位崩溃的最快线索**（异常代码能区分
  "Python 异常被 qFatal" 和 "原生访问越界"）。

## 10. 第二轮反馈修的三个问题

### 10.1 「继续阅读」总是跳到第一章
- **现象**：从书架点进一本书，按钮显示「继续阅读」，点下去却总是第一章。
- **原因**：`_fill_catalog()` 只给"上次读到的那一章"加了 `▶` 标记并滚动过去，
  **没有调用 `setCurrentItem()`**；于是 `catalog.currentRow()` 是 `-1`，
  而 `_on_read_clicked()` 写的是 `index = current if current >= 0 else 0` → 回落到 0。
- **修复**：填充目录时把进度那一章设为当前行；点击时若没有选中行则用记住的
  `progress.index`，不再硬编码 0。
- **验证**：两个独立进程跑完整流程——进程 A 读第 4 章并滚动到 500px 后关闭，
  进程 B 重新打开 → 书架 → 「继续阅读」→ 落在第 4 章且滚动位置恢复到 500px。
- **教训**：进度"存了"和"用上了"是两件事，UI 的选中状态也要跟着恢复。

### 10.2 阅读时左侧栏碍眼
- 顶栏加「☰ 侧栏」按钮 + `Ctrl+B`；进入阅读器自动收起、返回目录自动恢复；
  状态写进配置（`sidebar_visible`），下次启动保持；设置里可关闭自动隐藏。
- 实现要点：隐藏用 `setVisible(False)`（比把分隔条拖到 0 更好恢复），
  重新显示时用 `QTimer.singleShot(0, ...)` 恢复原宽度。

### 10.3 经常被"拒绝访问"（403/429）
分两类原因，对应不同解法：

| 原因 | 解法（本次已做） |
| --- | --- |
| 请求头太"素"，被站点一眼认出是脚本 | 补齐 `Sec-Fetch-*`、`sec-ch-ua*`、`Upgrade-Insecure-Requests` 等；图片请求单独用 `Sec-Fetch-Dest: image`；带 Referer 时把 `Sec-Fetch-Site` 切成 `same-origin` |
| 同一站点被瞬间打太多次（尤其封面） | ① 按站点排队限速（`_reserve_slot` 在锁内预约时刻、锁外 sleep，同站串行、异站互不阻塞，间隔带 ±35% 抖动）；② 封面改成**只在卡片可见时下载 + 并发上限**（默认 2），失败不重试 |

> 还有一类是真正的人机验证（Cloudflare 等），纯 HTTP 抓取过不去；
> 文档里讨论过"无头浏览器 + Cookie 桥接"的方案，暂未实施（体积与合规代价）。

## 11. 双页分栏的三个坑（第三轮反馈）

### 11.1 分页高度没扣文档边距 → 每页最后一段被裁掉
- **现象**：双页模式下左右两栏底部都露出半截文字，两栏内容"接不上"。
- **原因**：分页时用 `viewport.height() - 4` 当可用高度，但正文用的是
  `document().setDocumentMargin(26)`，上下各占 26px——实际可画高度只有
  `viewport - 52`，于是每页多塞了约 50px 的内容。
- **修复**：改用文档坐标判断——`blockBoundingRect().bottom() > viewport - margin`
  就从这一段开始新页（含段后间距一起判断，放不下就整体留到下一页，符合阅读习惯）。
- **验证**：遍历所有页，断言 `document().size().height() <= viewport().height() + 2`，
  当前 0 页超标（修复前是每页都超标）。

### 11.2 滚轮在正文上只滚动单栏
- **原因**：`QTextBrowser` 是 `QAbstractScrollArea`，wheel 事件先被它消费，
  根本传不到 `ReaderView.wheelEvent`。
- **修复**：在事件过滤器里拦截两栏 viewport 的 `QEvent.Wheel`：
  翻页模式下统一整屏翻页；仅当"某段比整页还高、该页确实需要页内滚动"时才放行。

### 11.3 双页时每栏太窄
- **原因**：早期实现是"总宽固定为 content_width，两栏平分"，
  结果 820px 的窗口每栏只有 378px，一行放不下几个字。
- **修复**：**每栏按单页宽度**取 `min(content_width, (可用宽 - 栏距) / 2)`——
  宽屏上两栏都是 820，窗口不够宽才等比缩小。

> 附带：正文上方新增**常驻章节标题**，解决"跳章时只有一瞬间空白、不知道当前是哪一章"。

### 11.4 修 11.1 时又踩了一个坑：分页用了绝对坐标
- **现象**：修完 11.1 后，每章只有第一页装满文字，**后续每页只剩一段**。
- **原因**：`rect.bottom() > viewport - margin` 里的 `rect` 是**文档绝对坐标**，
  于是第一页之后每个段落的底部都超过阈值 → 每段都被判成"放不下" → 一段一页。
- **正确做法**：要和"本页第一段的顶部"比较：
  `rect.bottom() - page_top > viewport - 2*margin`，换页时把 `page_top` 更新为新页首段顶部。
- **教训**：涉及坐标的判断，先想清楚是"绝对坐标"还是"相对当前页的偏移"。

### 11.5 章节标题栏挡住了鼠标 → 顶部浮条唤不出来
- **原因**：鼠标移到窗口顶部时，光标其实落在**章节标题栏**（或画布空白）上，
  而不是正文视图的 viewport 上；事件过滤器只装在 viewport 上，所以收不到 MouseMove。
- **修复**：给 `canvas`、`page`、`chapter_header` 也开 `setMouseTracking(True)` 并装过滤器，
  任意位置移动都能唤出浮条。

### 11.6 章首标题（新增功能）
- 每章正文开头加一段**大字号居中标题**（字号 = 正文字号 + 4，加粗，段后留白），
  只在章节第一页出现；`_render_into(..., heading_first=True)` 控制样式。
- 注意：标题作为第 0 段进入段落列表，所以 `block_index` 语义整体后移一位——
  旧进度会落在标题那一段（无害）。

### 11.7 行级分页：`QTextLine.height()` 不是行步进（第四轮反馈，最关键的一个）

- **现象**：双页模式下仍有约三分之一的页底部被裁掉（自检实测 33 页里 10 页超标，
  `doc_h=817` 而 `viewport=812`），偶尔还会因为"某段太高"冒出页内滚动条。
- **根因**：段落格式用了 `setLineHeight(line_height * 100, ProportionalHeight)`
  （默认 190%）。此时 `QTextLine.height()` 返回的只是**文字本身**的高度，
  行与行之间真正的步进是 `height × 行距倍数`：正文 30 × 1.9 = **57**，
  章首标题 37 × 1.9 = **70.3**。原分页代码按 `line_top + line.height()` 累加，
  一页就多塞了 2~3 行（实测每行少算 27px），底部自然被裁掉。
- **实测模型**（离屏打印每一行/每一块的坐标得出，误差 0）：
  - 行步进 = 相邻行的 `y` 之差；最后一行 = 下一块顶部 − 本块顶部 − 本块下间距。
  - 文档高度 = 最后一行底部（含步进）+ **一个** `documentMargin`；
    最后一块自己的下间距**不计入**文档高度。
  - 一页可用高度 = `viewport - 2 × documentMargin`，判断用
    `行底部(含步进) - 页顶 ≤ 可用高度`。
- **修复**：新增 `_line_advance()`（相邻行 y 差 / 用块占位反推最后一行）与
  `_block_span()`（下一块顶部 − 本块顶部 − 下间距），分页改用真实步进累加。
- **验证**：33 页 0 溢出；页面填充率 min 0.917 / avg 0.963（不浪费版面）；
  自检新增"所有页均不溢出（行级分页）"和"每页都装满（不是只塞一行）"两条结构性断言，
  界面自检 136/136、单元测试 66/66 通过。
- **教训**：凡是"按高度分页"，先确认拿到的 height 是**内容高度**还是**行步进**；
  比例行距下两者差一倍。

## 13. UI 重构 P1（信息架构）踩的坑

### 13.1 浮层不能进布局
- **背景**：搜索面板 / 目录抽屉 / 遮罩要"盖"在页面上。
- **做法**：它们都是 `centralWidget()` 的子控件，**不加入任何布局**，
  由 `MainWindow._layout_overlays()` 在 `resizeEvent` 与打开时统一 `setGeometry()`。
- **坑**：一开始想把抽屉塞进 `QSplitter`，结果 `setSizes` 与动画互相打架；
  方案里已经预判到（见风险表），照做即可。
- **顺序**：遮罩 → 浮层 → 轻提示依次 `raise_()`，否则遮罩会盖住面板。

### 13.2 「继续阅读」差点因为目录改抽屉而回退
- 旧实现靠 `catalog.currentRow()`（"目录里选中了哪一行"）决定跳哪一章，
  目录一旦搬进抽屉、详情页不再常驻列表，这个值就没有意义了。
- **新做法**：`BookView.reading_index()` 只认 `_progress_index`（上次读到的章节序号），
  抽屉里的 ▶ 高亮纯属展示。自检里那条回归断言（点「继续阅读」打开的是上次那一章）
  **原样保留**，并额外断言 `reading_index()` 的数值。
- 后续按反馈把首页的「继续阅读」大卡与「最近阅读」横排也去掉了：首页只剩书架网格，
  续读入口收敛到**详情页主按钮**这一条路径。于是 `LibraryView.continue_requested`
  与 `MainWindow._continue_index`（"打开详情后自动续读"分支）一并删除，不留死代码。
- 历史记录（`library.history()`）仍然照常写：它记的是进度，只是不再上首页。

### 13.3 简介"默认 3 行"不能用 `sizeHint()`
- **现象**：`intro_label.sizeHint().height()` 在标签被限高之后返回的是**限高后**的高度，
  于是"要不要显示展开按钮"永远判成不需要。
- **修复**：用 `QFontMetrics.boundingRect(QRect(0, 0, 宽度, 10000), TextWordWrap, 文本)`
  量一次全文高度，再和 `lineSpacing × 3` 比。自检断言"简介默认限高 3 行"。

### 13.4 封面节流在"不可见页面"里会停住
- `_pump_cover_queue()` 只处理**可见**的卡片，这是为了省流量；
  但书架首页刚启动时如果还没显示，队列就空转。
- **修复**：`show_library()`、`open_search_palette()` 里各 `start()` 一次节流定时器，
  等控件真正可见后再消费队列。

### 13.5 废弃配置键要主动清理
- `sidebar_visible` / `auto_hide_sidebar` / `splitter_sizes` 不再使用，
  但老用户的 `config.json` 里还在。`AppConfig.load()` 现在会把这些键
  **读出来就丢掉**（`DEPRECATED_KEYS`），避免残留值被别处误读。

### 13.6 自检断言迁移策略
- 方案第 7 节要求"不要删断言，只改断言对象"。实际按映射表逐条改写：
  侧栏 → 抽屉、搜索框 → 浮层输入框、卡片 → 结果行、书架卡片 → 网格格子。
- 结果：自检 **136 → 162 条**，全部通过；单元测试仍是 **66 条**全通过
  （本轮只动界面层，抓取逻辑零改动）。

### 13.7 浏览历史（右上角 🕘）的三条约定
- **为什么另开一个 `history.py` 而不是塞进 `library.py`**：
  `library` 是"一本书一份最新进度"（要能回答"继续读到哪"），
  而浏览历史要的是"每一次动作一条流水"（要能回答"我什么时候看过什么"）。
  两者查询方式相反，混在一份 JSON 里既难写也容易互相覆盖。
- **去重规则**：只有"**紧挨着的、完全相同的动作**"（同书 + 同类型 + 同章节）
  才合并为一条并刷新时间（窗口 90 秒）。中间隔了别的动作就各记一条——
  这样来回切页不会刷出一堆重复行，但"早上看过、晚上又看"仍然是两条。
- **流水要有上限**：`MAX_ITEMS = 500`，超出丢最旧的，避免 `history.json` 无限膨胀。
- **踩坑**：写单测时又用了 `tempfile.mkdtemp()`，在受限环境里系统临时目录**不可写**
  （`PermissionError: [Errno 13]`）。测试统一改用工作区内的 `tests/.tmp/`，
  与 `test_errors.py` / `test_importer.py` 保持一致。

## 14. UI 重构 P2（打磨）踩的坑

### 14.1 动画不能变成"状态"的唯一来源
- **坑**：抽屉/浮层改成淡入淡出后，若 `is_open()` / `is_bar_visible()` 仍返回
  `isVisible()`，那么"刚调用 close、动画还在跑的 200ms"里状态是错的，
  逻辑与测试都会飘。
- **做法**：每个带动画的控件维护显式的 `_shown_state`，显示/隐藏**立刻**改状态，
  动画只负责视觉；淡出结束后再真正 `hide()`（`widgets._finish_hide()` 会先检查
  `_shown_state`，中途又被显示就跳过隐藏）。
- **副产品**：`show_bars()` 后 `bars_visible()` 立刻为真，自检不用 sleep。

### 14.2 `QPropertyAnimation` 会被垃圾回收
- 创建了动画对象却不保存引用，函数一返回它就被回收，表现是"偶尔不动画"。
- **做法**：`widgets._keep()` 把动画挂到控件上（`widget._animation`）；
  自检也顺便用它断言"动画确实在跑、时长 250ms"。

### 14.3 抽屉动画与布局定位的顺序
- 抽屉的最终位置由主窗口 `_layout_overlays()` 用 `setGeometry()` 决定。
  如果先 `open_drawer()` 再布局，滑入目标就可能是旧尺寸，动画结束会"跳"一下。
- **做法**：主窗口先摆好遮罩/抽屉（`_layout_overlays()`）再调 `open_drawer()`；
  抽屉只做 `slide_in(屏幕左外侧 → 当前 x)`。

### 14.4 `QGraphicsOpacityEffect` 会连子控件一起半透明
- 所以只给"整体淡入淡出"的容器加（浮层、遮罩、浮条），**不给正文视图加**；
  浮层关闭后效果仍留在控件上，下次淡入直接复用，不反复 new。

### 14.5 自检里"短章节"会把相对断言带偏
- **现象**：`滚轮在正文上翻页 0 -> 0`、`双页翻屏生效 0 -> 0` 偶发失败。
- **根因**：联网搜索命中的书不同，某一章可能只有 272 字（卷首说明之类），
  整章只有一屏——滚轮/翻页自然会"进下一章"，`_spread` 停在 0。
  这不是代码 bug，而是断言依赖了网络内容。
- **修复**：分页相关断言改用**内容量确定的合成正文**
  （`ChapterContent(paragraphs=[...80 段...])` 直接喂给 `reader.set_content()`），
  不再受真实章节长短影响；滚动恢复那段先往后找一章
  `scrollBar().maximum() >= 700` 的长章节再断言。

## 15. 离屏截图里没有文字（最隐蔽的一个坑）

### 15.1 现象
项目一直把 `tests/shots/*.png` 当作"界面效果图"（README 里也这么写），
但**这些图里一个字都没有**：只有封面图、按钮色块和边框线。
最典型的是 `14_reader_two_page.png` —— 整个双页阅读器是**纯米黄空白**（5.6 KB）。

### 15.2 根因（实测）
离屏平台**默认不加载任何字体**：

```
offscreen 下可用字体族数量 = 0
画中文到 QImage 后，非背景像素 = 0        ← 文字完全没画出来
```

字体族为 0 时，QLabel / QPushButton / QTextBrowser 的文字绘制全部为空；
只有 `QPixmap` 自绘（封面）、QSS 背景色块、`border` 画的线能出来。
所以"有颜色 ≠ 有内容"，而当时的颜色统计断言照样通过。

### 15.3 更严重的后果：统计类断言是**假通过**
`check("结果页渲染正常", stats["colors"] > 40)` 这类断言只统计颜色多样性：
一张"全图只有色块、一个字都没有"的截图完全能满足 `colors > 30`、`lum > 150`。
于是 **205 条断言全绿，但其中所有图像统计项什么都没验证**——
这也解释了为什么"双栏被裁""浮条不出现"这类问题一直是用户先发现、而不是自检先发现。

### 15.4 修复
1. **在 `QApplication` 创建之前**设 `QT_QPA_FONTDIR` 指向系统字体目录：
   Windows `%WINDIR%\Fonts`、macOS `/System/Library/Fonts`、Linux `/usr/share/fonts`。
   实测字体族 **0 → 107**。
2. 兜底：若仍为 0，用 `QFontDatabase.addApplicationFont()` 手工注册几个字体文件
   （实测 `msyh.ttc`/`simsun.ttc`/`simhei.ttf`/`segoeui.ttf` → 6 个族，文字可画）。
3. 新增两条断言把这个盲区钉死：
   - `离屏环境已加载字体（否则截图里没有文字）` → 107 个字体族
   - `离屏渲染能画出文字（截图验收的前提）` → 往 QImage 画中文并数非背景像素，**1738 px**（原为 0）

### 15.5 连带发现的测试脆弱性
字体一加载，文字度量变化 → 分页边界跟着变 → 有 2 条断言开始失败：

```
FAIL 默认首行缩进生效（2 字符）  indent=0.0px
```

不是产品回归：那两条读的是"**当前页第一块**"的缩进，而翻页模式下第一块
可能正好是**续页片段**（`continuation` 格式，缩进按设计就是 0）。
改成"本页所有块里最大的缩进"后恢复（实测 62.0px）。

### 15.6 教训
- **"看起来在验证"和"真的在验证"是两件事**：颜色统计 ≠ 内容渲染。
- 验收链路本身也要有断言（字体在不在、文字画不画得出来），
  否则整条链路是空转的，而且**不会报错**。
- 换环境（离屏/CI/容器）时先问一句"这个环境有字体吗"。

## 16. 首轮视觉验收发现的 3 个问题（已修）

截图能看之后，第一次用"肉眼 + 像素"过了一遍 17 张图，抓到 3 个数值断言完全覆盖不到的问题：

### 16.1 夜间主题下"浅色外壳夹着深色正文"
- **现象**：夜间阅读时正文区是 `#1B1F23`，但主窗口**顶栏与状态栏仍是暖白** `#F7F3E9`。
- **根因**：P0 只让阅读区内部（canvas / page / 浮条）跟随了主题，**应用级的顶栏与状态栏**没管。
- **修复**：新增 `ReaderView.theme_changed` 信号 → `MainWindow._sync_shell_theme()`：
  在阅读器页面时把 `#topBar` / `QStatusBar` 按当前阅读主题重新着色（含文字与图标颜色），
  离开阅读器时清空样式表回到 app 级暖白。
- **坑**：一开始只在 `settings_changed` 上挂钩，而**直接调 `apply_settings()` 换主题不会发这个信号**，
  于是自检里"手动改主题"的路径没生效 —— 断言当场抓出来了（`夜间主题下顶栏跟随变暗 #f7f3e9`）。
- **断言**：夜间主题下顶栏/状态栏中心像素 `lightness < 110`；离开阅读器后 `> 200`。

### 16.2 对话框底色比主窗口白一档
- **现象**：设置对话框看着比主窗口"白"，采样为空区域是 `#FBF9F3`（卡片色 `BG_SURFACE`）。
- **根因**：`QDialog` 没有暖白规则，可见底色主要来自 `QTabWidget::pane`，而它用的是卡片色。
- **修复**：`QDialog, QTabWidget::pane { background: BG_APP; }`，分组框仍用 `BG_SURFACE` 形成层次。
- **断言**：设置对话框中心像素 == `#F7F3E9`。
- **更正**：我最初目测判成"纯白 `#FFFFFF` 违规"，**采样后才发现是 `#FBF9F3`** —— 目测结论不可直接采信。

### 16.3 封面角标只有文字、没有深色药丸底
- **现象**：书架格子的进度角标看起来是"白底浅字"，没有设计里的深色半透明标签。
- **根因（Qt 样式表级联）**：`CoverLabel` 自己 `setStyleSheet("background: ...")` —— 
  **无选择器的声明会作用于该控件及其所有子控件**，而它来自更近的祖先，
  于是把 app 级 QSS 里的 `#coverBadge { background: rgba(45,41,35,205) }` 盖掉了。
- **修复**：给角标单独设一条**带选择器**的样式表（`#coverBadge { ... }`），更具体 → 一定胜出。
- **断言**：抓封面图，统计角标矩形内"深色像素 > 浅色像素"（实测深色占比 70%）。
- **坑**：断言最初采样**角标正中心**，正好落在字形上（`#c0beb9`）→ 误报失败；
  改成按区域统计占比才稳。

### 16.4 方法论：看图要有，但结论必须用像素复核
这一轮里我**两次目测出错**：
1. 在整图缩放预览里把夜间主题的深色顶栏看成了"浅色"（实际 `#1B1F23`）；
2. 把对话框的 `#FBF9F3` 判成"纯白违规"。

正确做法：**先看图发现问题 → 再裁出局部放大 / 采样像素确认 → 最后才写结论**。
本次用"裁剪 + 放大 + 拼接成证据图"的方式一次确认了 5 处，比反复看整图高效得多。

## 17. 浏览历史：从"流水"改成"一本书一条"

### 17.1 需求与问题
原来的实现是**流水**：打开一次详情记一条、每读一章再记一条，
于是一本《斗罗大陆》在历史里能刷出 6 条（切章越多越多），既重复又难用。

### 17.2 新规则
| 项 | 改法 |
| --- | --- |
| 去重 | **按书去重（upsert）**：同一本书只留一条，位置与时间刷新到最新 |
| 写入时机 | 打开详情时记一条；**章节信息只在"离开阅读器"或"关闭应用"时写**（不再每切一章写一次） |
| 上限 | `MAX_ITEMS` 500 → **30**（一本书一条，30 条足够覆盖"最近看过的书"） |
| 保留章节 | 只打开详情（不带章节）时**继承**上一条的 `chapter_index/title/url`，否则"点历史回到那一章"会失效 |

进度不受影响：`library.update_progress()` 仍然实时保存，历史只负责"最近看过哪些书"。

### 17.3 踩到的两个小坑
1. **重开详情会抹掉章节信息**：最初的 upsert 直接用新记录整条替换，而详情记录不带章节
   （`chapter_index=-1`），于是历史条目失去了"读到哪里"。修法见上表最后一行。
2. **断言写在了"清空历史"之后**：自检里"重开详情不丢章节"这条一开始放在清空历史之后，
   历史已空 → 没有 previous 可继承 → 误报失败。**顺序敏感的断言要挨着被测行为写**。
   定位方法：把断言信息补全（打印全部记录），一眼看出列表已空。

## 18. 本地 TXT / EPUB 导入（实现要点）

### 18.1 做法：把本地书接成"一个书源"
新增 `sources/local.py` 实现 `BaseSource` 的三个方法，`Book.url` 用伪地址
`local://<id>`。这样**目录抽屉、阅读器（分页/主题/位置记忆）、书架、"继续阅读"、
搜索浮层全部自动可用**，界面层几乎不用写特殊分支——这是最省力的接法，
也是"别只能导入不能阅读"的关键。

配套：
- `localbooks.py`：导入时把文件**复制**到数据目录 `local_books/`，元数据（书名/作者/章节表）写 `local_books.json`；
- `local_parse.py`：编码识别、TXT 切章、EPUB（OPF spine + 封面）；
- `tasks.LocalImportTask`：解析放工作线程（几 MB 的 TXT 要一两秒）。

### 18.2 TXT 切章的三个坑
1. **正文行被当成标题**：最初的正则 `^第X[章节回]...$` 把
   "第二章的正文内容，也足够长。" 也匹配了，一本 3 章的书切出 6 章。
   修法（`is_chapter_title`）：
   - 含句读（`。！？，；`）直接判否；
   - `第X章` 后**有分隔符**（空格/：/、）时整行 ≤ 30 字，**没有分隔符**时整行 ≤ 12 字。
2. **开头的"书名/作者"被当成一章「前言」**：下载站的 TXT 常在开头写
   `书名：xxx / 作者：xxx`。修法：解析这段元信息 → 直接用作书名作者（比文件名可靠），
   并且当这段除元信息外**不足 40 字**时整段丢弃，不再生成「前言」。
3. **认不出章节就废了**：加兜底——匹配少于 2 个标题时按每 4000 字切块，
   标题叫「第 N 部分」，保证导进来一定能读。

### 18.3 其它两个决定
- **按内容摘要去重**：同一本书改名后再导入（内容相同）会**替换**旧记录而不是新增，
  书架里不会出现两条；判断依据是文件的 SHA-1，不是文件名/书名。
- **本地书源不参与"健康度自动禁用"**：它不联网，失败原因通常是文件被删，
  提示"建议重新导入"比禁用书源更合适。

### 18.4 自检里踩的坑：等待条件太松 = 读到上一章
新加的端到端断言一开始失败在"本地书能读正文"——因为等待条件写成了
`wait_for(lambda: bool(window.reader._paragraphs))`，而**阅读器里还留着上一章的内容**，
条件立刻就成立，于是断言读到了旧章节。

同理，`local_books.count() >= 2` 在导入**循环中**就会变真，
而"写进书架 + 刷新首页"要等 `finished` 回调。

**规矩**：异步流程的断言要等**最终状态**，不能等"非空"——
```python
wait_for(lambda: "第二段正文内容" in "".join(window.reader._paragraphs), 40)
wait_for(lambda: any(t.book.title == "本地测试书" for t in window.library_view.tiles()), 90)
```

## 19. EPUB 三个问题的修复（乱码 / 插图 / 分卷目录）

用户实测反馈：导入《诡秘之主》插图版后「**很多章是乱码**、**插图不显示**」，
并要求「**部/卷**在目录里可折叠、默认收起」。三件事的根因与修法：

### 19.1 60% 章节乱码：拿**截断的前缀**做严格解码
- **实测**：那本书 1408 个 HTML **整文件严格 UTF-8 解码 100% 通过**，
  但只取前 4KB 严格解码只有 **569/1408 通过** —— 差异的 839 个文件被误判成 GBK → 乱码。
- **根因**：中文 UTF-8 是 3 字节/字，4096 不是 3 的倍数，很容易把一个字切成两半；
  `head.decode(encoding)` 严格模式遇到尾部不完整直接抛 `UnicodeDecodeError`，
  于是"合法的 UTF-8"被判成 GBK。
- **修法**（`local_parse.detect_encoding`）：
  1. **优先信任文件自己声明的编码**（XML 声明 / `<meta charset>`）——EPUB 里这是权威来源；
  2. 判定用**增量解码器**（`codecs.getincrementaldecoder(enc)().decode(prefix, final=False)`），
     尾部不完整当作待续字节，只有真正的非法序列才报错；
  3. 顺序：BOM → 声明 → UTF-8 → GB18030 → Big5。
- **影响面**：TXT 同样受影响（同一套检测）。**已导入的 TXT 建议重新导入**
  （章节偏移是按错误解码算出来的）；EPUB 不用重导（正文是读取时才解码）。
- **回归断言**：`test_utf8_not_misdetected_when_prefix_splits_a_char`、
  `test_all_prefix_lengths_decode_as_utf8`（多个截断点都不许误判）。

### 19.2 图片路径按 OPF 目录解析（应相对**文档**）
- `src="../Images/C1.png"` 是相对**当前 XHTML 文件**解析的，而我把 OPF 所在目录当基准，
  于是 `OEBPS/Text/../Images/C1.png` 被算成 `Images/C1.png`，读不到图。
- 修法：`read_epub_chapter_rich` 里用 **href 自己的目录**作基准，并加注释说明。

### 19.3 图片占位被"严格广告过滤"吃掉
- 最初用 `@@IMG0@@` 这种占位，而严格模式会丢掉**整行纯 ASCII**（防站点推广行），
  占位连同图片一起被清掉 —— 现象是"图片没解析出来"，实际是被过滤了。
- 修法：占位改成 `U+FFFC + 序号 + U+FFFC`：非 ASCII（躲过严格模式）、
  带序号（顺带避免"连续两行相同被去重"）。
- 阅读器侧：图片段落固定是**一个** `U+FFFC` 字符 ——
  分页/进度用的字符偏移完全不受影响；而且测量渲染与页面渲染走同一条路径，
  **图片高度会被正确计入分页**（不会把图挤到页外）。
- 图片按段落序号存在 `ChapterContent.images`，渲染时 `QTextDocument` 直接插入图片；
  解码结果按"章节 + 段落"缓存（同一张图被上千章引用，不缓存会卡）。

### 19.3.1 插图画成"图片缺失"破图：忘了 `addResource`
- 用户实测反馈："这次出现了，但是不显示图标" —— 位置对了，画出来的是 Qt 的**破图图标**。
- **根因**：`QTextImageFormat.setName("local-image://…")` 只是给文档一个**名字**，
  文档要按名字去资源表里取图；我只 insertImage、**没 `document.addResource(...)`**，
  于是查不到资源 → Qt 画"图片缺失"占位图。
- **修法**：插入前把 QImage 注册进文档：
  ```python
  document.addResource(QTextDocument.ImageResource, QUrl(name), image)
  ```
- **断言也要跟上**：原来只断言渲染出来的 HTML 里有 `<img`——**破图同样满足它**，
  所以断言是绿的、界面是坏的。改成断言资源真的注册了：
  ```python
  check("EPUB 插图已注册为文档资源",
        not doc.resource(QTextDocument.ImageResource, QUrl(name)).isNull())
  ```
  **教训：断言要盯着"结果对不对"，而不是"有没有那个标签"。**
- 另外加了**高度上限**（页面高度的 62%）：真实那本书每章开头一张 600×600 的徽记图
  （1394 章都有），不限高就会占满整页。实测缩放后图片块 758×513（上限正好 513）。

### 19.4 NCX 目录：navPoint 在 `<navMap>` 里面
- `_parse_ncx_toc` 一开始从 `<ncx>` 根节点找 `navPoint`，**一个都找不到**——
  真实结构是 `<ncx><navMap><navPoint>…`。修法：先定位 `navMap` 再遍历。
- 顺带解决"章节标题不准"：改成**优先用 NCX 的标题**
  （这本书原来的标题是从 HTML 里猜的 `chapter 10 - 0`，NCX 里是 `第九章 笔记`）。

### 19.5 分卷（部/卷）折叠
- **TXT**：`第X部/卷/集/册/篇`、`上/中/下册` 识别为**分组**而不是章节；
  卷标题行不进任何章节；卷标题后面的"卷首语"归到下一章（不丢内容）。
- **EPUB**：用 NCX/nav 的**嵌套层级**（有子节点的 navPoint 就是"部"）。
- 通用组名（`正文`/`目录` 这类）在组内章节 < 20 时拆掉，免得前置页被折叠起来。
- 目录抽屉从 `QListWidget` 换成 `QTreeWidget`：默认全部收起，
  **当前章所在的分组自动展开**；筛选时自动展开命中的组、隐藏没命中的；可一键全展开/收起。
- **章节索引不变**（分组只是元数据），所以进度、"继续阅读"、位置记忆全都不受影响。

### 19.6 这一轮踩的测试基建坑（都值得记）
1. **手写的十六进制 PNG 是坏的**：`IDAT: incorrect data check`。
   字节层面的断言（`startswith(b"\x89PNG")`）照样通过，只有真正解码才暴露 ——
   于是"插图窗口显示 0×0"查了半天。修法：用 `zlib` + CRC **现场生成**合法 PNG，
   并补一条 CRC 校验的单元测试。
2. **`QListWidgetItem.setIcon()` 要 `QIcon`**，给 `QPixmap` 会 `TypeError`（直接崩脚本）。
3. **详情缓存丢字段**：`_detail_to_cache` / `_detail_from_cache` 是成对的，
   新增 `Chapter.group` 时只改了一边 → 第二次打开这本书（命中缓存）目录树就塌成一层。
   **教训：缓存往返的字段要成对维护，最好由一条测试覆盖"二次打开"。**
4. **自检样本没有图片**：新加的插图断言报"0 张"，因为我在自检里生成的 EPUB 只有文字。
   **样本要能覆盖被测行为**，否则断言是在验证空气。

## 20. 翻页时"内容缺了一段"：三层根因（用户实测反馈）

现象：双页翻页模式下滑一次滚轮，**中间整段内容凭空消失**；TXT / EPUB 都有，
而且"偶尔同一章还能顺畅阅读"。挖下去是**三个独立问题叠在一起**：

### 20.1 一次滚动被拆成多个事件 → 一次翻好几屏
滚轮驱动和触摸板经常把**一次物理滚动拆成多个小事件**（-60 + -60，甚至 -30 × 4），
而当时的代码是"**来一个事件就翻一屏**"：

| 滚轮事件 | 修复前前进屏数 |
| --- | --- |
| 一次 -120（标准一格） | 1 |
| 一次 -60 | 1 |
| 一次 -30 | **1** ← 任何非零都翻页 |
| **一格被拆成两个 -60** | **2** ← 内容就是这么丢的 |

**修法**：按"格"累计（`WHEEL_NOTCH = 120`），凑够一格才翻**一屏**（多余的当量直接丢），
再用 `WHEEL_COOLDOWN = 0.12s` 抑制同一格的连发事件。连续两格（间隔 0.4s）仍翻 2 屏 ✓。

### 20.2 分页用"整篇文档的行坐标"推算 → 个别页多塞 2 行，底部被裁
整篇文档里排的是**完整段落**，页面上排的是**段落片段**（续页片段不带首行缩进，
断行位置可能不同），图片块的真实高度也只有渲染出来才知道。实测某些页因此多塞 103px：

| 页 | 分页估计页高 | 实际内容高 |
| --- | --- | --- |
| 3（含跨页段落） | 734 | **836** ← 超出 61px，底部被裁 |
| 其余页 | 714~766 | 714~769 ✓ |

**修法**：改成**渲染候选页、量它自己的行**（`_paginate` + `_last_fitting_offset`），
与真实翻页走同一个渲染入口。分页耗时 ~0.24s/章，只在换章/改设置/改窗口时跑。

顺带修掉的三个实现坑：
1. **`block.layout()` 是空的**——Qt 布局按需进行，必须先调 `blockBoundingRect()` 触发布局；
   顺序反了每页只前进一个字（实测一章分成了 **2898 页**）。
2. **坐标系混用**——页面文档里 `block.position()` 是页内坐标，`_page_offsets` 要全章偏移，
   必须按片段映射回去。
3. **`heading_first` 不一致**——分页候选渲染与页面渲染必须都传 `True`。

### 20.3 滚动条把自己"粘"住 → 分页宽度与显示宽度不一致
最后剩下的那一页（正是用户截图里那章）：

```
左页 viewport 宽 598（不是 608）  滚动条 max=76（AsNeeded）  文档高 904 > 视口 828
```

**反馈环**：某页稍溢出 → 打开滚动条 → viewport 从 608 缩到 598 → 文字重排成更多行
→ 溢出更多 → 滚动条一直开着；而分页是按 **608** 算的 → 底部几行被裁。
**修法**：翻页模式**一律 `ScrollBarAlwaysOff`**（宽度恒定）。超大插图有高度上限
（62% 页面高），不会出现"单块比一页还高"的死角。

### 20.4 这次真正救了命的两件事
1. **像素级判据**：抓 `viewport()` 的图，从底部往上找"有 ≥4 个非背景像素"的行。
   之前的"无溢出"断言用的是 `document().size().height()`——**和分页同一个模型**，
   属于循环验证，一直是绿的而界面是坏的。
   注意要抓**稳定帧**（连续两次 `grab()` 一致），否则会抓到上一帧、误报"贴底"。
2. **反向对照**：把旧公式临时装回去，确认新断言**真的会红**——
   否则它可能什么都没验（同一天已经栽过两次：坏 PNG、`<img>` 断言）。

## 21. 插图被"行距"放大 + 章末多出空白页（用户实测反馈）

用户接上一轮修复后的反馈：**"图标不在左栏""翻页后左栏下半截必定空白""有些章节最后一页是空白的"**。
两个独立 bug，都在分页/渲染这一层。

### 21.1 图片那一行被套用了 190% 比例行距
dump 一章的页面（1920×1440 窗口，每栏 820px）：

```
块0 top=26   h=34   第一百七十七章 探索之后
块1 top=127  h=600  line.height=600  _block_span=1140   ← 图片实际 600，占位却算 1140
块2 top=1279 h=29   灰雾之上，见白银城探索小队踏上归途而巨人王宫   ← 被推到 1152px 之后
```

**根因**：段落格式设了 `setLineHeight(190, ProportionalHeight)`，而插图的"那一行"
``line.height()`` 就是图片高度（600px）。Qt 把比例行距**同样套在图片行上**，
于是这一行的步进变成 600 × 1.9 = **1140px**：

- 图片下方凭空多出 **540px 空白**（"左栏下半截总是空的"）；
- 分页以为这块高 1140 → 标题 + 图片就超过一页 → **图片被挤到单独一页**，
  在双页模式下正好落到**右栏**（"图标为什么不在左栏"）；
- 窗口高度稍有变化，图片就在"和标题同页"与"自己一页"之间来回跳（很迷惑人）。

**修法**（`reader.py`）：
1. 插图段落的块格式显式设 `setLineHeight(100, QTextBlockFormat.SingleHeight)`
   —— 图片行不再被放大；
2. `_line_advance(..., is_image=True)` 对图片行直接返回 `line.height()`（图片高度），
   不乘行距倍数，和渲染行为保持一致。

修后同一章：图片块占位 600 ✓、正文紧接其后（间隙 12px = 段距）✓、页数 12 → 8 ✓、
**图片回到左栏第一页**（标题下方）✓。

### 21.2 分页会在章末多出一个空白页
```python
offsets.append(min(page_end, total))     # ← page_end == total 时追加了"总长"本身
```
最后一页的区间成了 `[total, total)` = **空页** → 用户看到"有些章节最后一页是空白"。
修法：`page_end >= total` 时直接 `break`（本页已经到章末，不该再加一个页起点）。

### 21.3 这两条的断言怎么写的
- **反向对照确认有效**（规约 §2.2）：把旧行为临时装回去，新断言真的会红——
  `FIXED: 图片块高=300 间隙=12px → 通过`；`OLD: 间隙=282px → 失败`。
- 自检样本的插图必须**够大**（用 400×300）：4×4 的小图看不出"被行距放大"的空白，
  断言会形同虚设。
- 章末空页断言需要翻页模式：`verify_ui` 到那一段时已经切回滚动模式，
  `_page_offsets` 是空的（第一版断言直接 `IndexError`），要显式切回翻页模式再测。

### 21.4 用"用户的窗口尺寸"复现
第一次复现没成功：我用 1360×880（测试窗口）时图片正好和标题同页；换成 **1920×1300**
才复现（可用高度 1195 < 标题 65 + 图片 1140）——**排版问题要按用户的窗口尺寸复现**，
差 50px 结论就相反。

## 22. 书架管理 / 快捷键 / 正文光标（用户实测反馈三连）

### 22.1「移出书架」不清任何东西，也没有"彻底删除"入口
用户问："重新导入 epub 时，第一次导入的我点了移出书架，不清楚缓存有没有被清"。
查下来：`Library.remove()` **只做 `self._data["books"].pop(key)`** ——
导入的文件、`local_books.json` 记录、章节/详情缓存、浏览历史、阅读进度**全都留着**；
而且界面上**没有任何入口**能彻底删掉一本导入的书。

**实测用户真实数据目录**（`%APPDATA%\NovelFound`）：

| 位置 | 情况 |
| --- | --- |
| `local_books/` | 无孤儿文件（旧记录是"重新导入去重"时连文件一起删的 ✓） |
| `cache/cache.db` | **41 行**仍指向已删的本地书（章节 39 + 详情 2） |
| `history.json` | 30 条里有 **2 条**指向已删记录 |
| `library.json` | 进度历史里 **2 条**指向已删记录 |

**修法**：
1. 「移出书架」与「删除本地书」分成两个动作——前者只隐藏（并提示"文件仍在本地库"），
   后者走确认框（**显示明细**：文件大小、缓存行数、会一并清掉的记录），
   然后级联删除：本地文件 + 封面 + 记录 + 缓存 + 浏览历史 + 阅读进度。
2. 新增「本地书管理」窗口（书架页右上角进入）：列书名/格式/章数/占用/导入时间，
   可删除、重新导入、打开文件位置；窗口里还有「**清理失效记录**」按钮。
3. 后端补了 `Library.forget` / `purge_stale_local`、`BrowseHistory.remove_book` /
   `purge_stale_local`、`Cache.delete_book` / `count_for_book` / `purge_stale_local`。
4. 用户那 45 处失效引用已清掉（书架/进度 2、历史 2、缓存 41，复查零残留），
   原文件备份成 `cleanup-backup-<时间戳>`。

**写这段时踩的坑（单元测试当场抓到）**：清理逻辑里拿 `is_local_url()` 去判断**记录键** ——
键是 `local|local://<id>`，用"以 `local://` 开头"去判永远不成立，于是一条都匹配不到。
新增了 `localbooks.is_local_key()` 专管记录键，并在文档串里写明区别。

### 22.2 方向键：不是"没绑定"，而是**根本没送到阅读器**
用户要"←↑ 上一页、→↓ 下一页"。查代码发现 `ReaderView.keyPressEvent` 里**早就有**
`PageDown/Space/PageUp/←/→` 的绑定 —— 但实测**按了没反应**：

```
事件发给 self.view（真实场景：正文控件持焦点）
  PageDown  屏 0->0    ← 完全没反应
  Space     屏 0->0
  Right     屏 0->0
事件发给 self.reader（绑定所在处）
  PageDown  屏 0->1    ← 只有直接发给阅读器才有效
```

**根因**：焦点在正文控件（`QTextBrowser`）上时，按键先被它自己消费掉（read-only 也会
消费方向键/翻页键），父控件的 `keyPressEvent` 收不到。**光加绑定没用，必须把按键拦下来。**

**修法**：
* 在 `view` / `view2` 上装 KeyPress 事件过滤器（和滚轮同一套路），转发给
  `_handle_key()`；`keyPressEvent` 也走同一个函数；
* 映射按要求重定：`←/↑` 上一页、`→/↓` 下一页、`Ctrl+←/→` 换章；
* 按用户要求**删掉**旧绑定（`PageUp/PageDown/Space/Home/End` 与"←→ 换章"）；
* 自检里对着**正文控件**发真实 `QKeyEvent`（不是发给 `reader`），确保走的是真实路径。

### 22.3 正文左上角那条"待输入的竖线"
来源是 `setTextInteractionFlags(TextSelectableByMouse | TextSelectableByKeyboard)`：
Qt 的 **`TextSelectableByKeyboard` 会提供可见文本光标**，位置在第 0 字是因为每次渲染后
`moveCursor(QTextCursor.Start)`；不闪烁与焦点/系统光标闪烁设置有关。

按用户选择改成 **只用 `TextSelectableByMouse`**：竖线消失，鼠标选中/复制照常
（自检断言 `textInteractionFlags() == TextSelectableByMouse`）。
