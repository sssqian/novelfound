# 开发过程问题记录（踩坑与解决）

本文记录本次开发（含环境搭建、抓取解析、界面、打包四个阶段）中**实际出现过并已解决**的
问题，供你复现/排查时参考。每条都按「现象 → 原因 → 解决」写，最后附一份经验清单
和需要手动清理的文件列表。

> 环境前提：本次开发跑在 **DSH 沙箱（文件策略 workspace-write）** 下，
> 只能写工作区目录。下面标注「沙箱限制」的问题**在你自己的普通桌面环境里不会出现**，
> 但代码里的防御性处理仍然保留，属于有益的健壮性改进。

## 1. 环境与依赖

### 1.1 pip 装不上依赖（Permission denied）
- **现象**：`pip install PyQt5 requests beautifulsoup4 lxml` 报
  `ERROR: Could not install packages due to an OSError: [Errno 13] Permission denied:
  ...\pip-unpack-xxxx\requests-2.34.2-py3-none-any.whl.metadata`
- **原因**：沙箱限制（不是包的问题）。pip 解包时要在临时目录里创建 `.whl.metadata`，
  该写入被拒绝；把 `TEMP/TMP` 指到工作区后依旧被拒（同一策略）。
- **解决**：绕过 pip，写了临时脚本 `_pyi_fetch.py`（已删除）——
  查 PyPI JSON API 挑兼容 wheel → 用 `urllib` 下载 → `zipfile` 解压到
  `.venv\Lib\site-packages`。PyQt5 等全部装成功。
- **你的环境**：直接 `pip install -r requirements.txt` 即可，无需这套绕行。

### 1.2 创建虚拟环境失败
- **现象**：`python -m venv .venv` 报
  `Error: Command '[...python.exe, '-m', 'ensurepip', ...]' returned non-zero exit status 1`
- **原因**：`ensurepip` 同样需要写临时目录，被沙箱拒绝。
- **解决**：`python -m venv --without-pip .venv` 建环境，再用 1.1 的方式把 pip 的 wheel
  解压进去；验证 `python -m pip --version` 正常。
- **你的环境**：`python -m venv .venv` 正常可用。

### 1.3 自写下载器选错了依赖版本
- **现象**：装完后 `import requests` 报 `ModuleNotFoundError: No module named 'cgi'`
  （Python 3.13 已删除 `cgi` 模块）。
- **原因**：版本排序用字符串比较，`"2.9.2" > "2.34.2"` 成立 → 选中了 2016 年的 requests 2.9.2；
  同时 ABI 标签匹配过宽，把 `cp311` 的 wheel 也当成兼容。
- **解决**：改成「数字元组比较 + 跳过预发布版 + 严格匹配 `cp313/abi3/py3-none-any`
  与 `win_amd64`」，并优先原生 `cp313` 轮子。

### 1.4 PowerShell / curl 无法访问网络
- **现象**：`Invoke-WebRequest` 报「基础连接已经关闭」，
  `curl` 报 `schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS`。
- **原因**：Windows schannel 在当前环境下拿不到 TLS 凭证，**不是沙箱、也不是网络不通**。
- **解决**：改用 Python 的 `urllib`/`requests` 做探测与抓取（实测 200 正常）。

### 1.5 控制台中文乱码 / UnicodeEncodeError
- **现象**：调研脚本打印中文变成 `������`；`print` 直接抛
  `UnicodeEncodeError: 'gbk' codec can't encode character ...`。
- **原因**：中文 Windows 控制台默认代码页 GBK，而脚本输出 UTF-8。
- **解决**：运行时设 `PYTHONIOENCODING=utf-8`，脚本内 `sys.stdout.reconfigure(encoding="utf-8")`，
  并把结果**写文件**而不是只打印。

### 1.6 数据目录不可写导致启动失败
- **现象**：`AppConfig()` 抛 `PermissionError: [WinError 5] 拒绝访问:
  'C:\Users\Shao\AppData\Roaming\NovelFound'`。
- **原因**：沙箱不允许写 `%APPDATA%`。
- **解决**：`config.data_dir()` 增加两级容错——
  ① 支持环境变量 `NOVELFOUND_HOME` 覆盖（顺带成为「绿色版/便携模式」功能）；
  ② 目标目录不可写时自动回退到系统临时目录，保证程序仍能启动。

## 2. 抓取与解析

### 2.1 中文关键词没做 URL 编码
- **现象**：探测脚本抛 `UnicodeEncodeError: 'ascii' codec can't encode characters`。
- **原因**：拼 URL 时直接塞了中文关键词。
- **解决**：统一用 `urllib.parse.quote(keyword, encoding=...)`。

### 2.2 候选站点大面积失效
- **现象**：手工列的 20 多个「笔趣阁」域名，多数 403 / SSL 失败 / 已改版。
- **解决**：从开源「阅读」App 的书源 JSON 里收割 **440 个候选域名**批量探测，
  最终筛出 3 个稳定可用源（和图书、蚂蚁文学、笔趣阁5200）并写入内置规则表。
  这也是「多书源 + 可自定义书源」设计的由来。

### 2.3 广告过滤误删正文容器（最隐蔽的一个）
- **现象**：某章正文显示成「我的书架 / 玄幻小说 / 排行榜…」等导航文字。
- **原因**：广告容器判定里有个宽松规则——只要 class/id 里含 `ad` 就删。
  而正文外层容器叫 **`content_read`**，结尾正好是 `ad`（re**ad**），
  于是整块正文被当作广告删掉，程序只能退而取全页最大节点（导航区）。
- **解决**：改成三层判定——
  ① `AD_TOKEN_RE` 按**词边界**匹配（`-ad`/`ad_`/`ads`…），`content_read` 不再命中；
  ② 广告 id 用专门正则 `AD_ID_RE`（`ad`/`adt1`/`cbad`/`ctad`/`cstad` 等）；
  ③ 增加 `SAFE_CONTAINER_RE` 白名单（content / read / list / dir…）永不当广告删。

### 2.4 正文容器"谁文本多选谁"选错
- **现象**：短章节里抓到的正文是导航+推荐位。
- **原因**：`pick_content_node` 原先在**所有候选选择器**里挑文本量最大的节点。
  外层 `div.content_read` 把导航、推荐一起算进去（445 字），
  反而比真正的 `#content`（319 字）更长。
- **解决**：改为**按选择器优先级**判断：先看规则里配的 `#content`，
  文本量达标就用它；全都不达标才退到第一个命中的选择器；最后才用全页最大块兜底。

### 2.5 目录顺序错乱（最新章节跑到最前面）
- **现象**：点开目录，第一条是「第二百三十六章 大结局」。
- **原因**：经典模板的目录里既有「《书名》最新章节」预览块，又有「正文」块；
  而蚂蚁文学把这两块塞进**同一个 `<dl>`**，靠 `<dt>` 分隔。
  整块跳过 → 目录全空；整块保留 → 预览块（倒序）排在前面。
- **解决**：目录解析改为**按 `<dt>` 分段**：优先取「正文」段；
  再按 URL **保留最后一次出现的位置**去重（自动剔除预览重复项）；
  最后用章节号统计升降比例，整体倒序时自动翻转。

### 2.6 搜索关键词编码与页面编码不是一回事
- **现象**：笔趣阁5200 搜索返回首页，没有结果。
- **原因**：该站页面是 GBK，但搜索 URL 里的关键词必须用 **UTF-8** 编码；
  我最初把「页面编码」直接复用成了「关键词编码」（GBK），站点解析不出来。
- **解决**：拆成两个字段——`encoding`（响应解码）与 `search_encoding`（关键词编码，默认 UTF-8）。

### 2.7 防盗版标记与文本节点碎片
- **现象**：正文里混进「和-图-书」；一句话被拆成两段。
- **原因**：和图书在正文里插入 `<acronym>`/`<samp>` 标记；删除这些标签后，
  BeautifulSoup 留下**相邻文本节点**，`get_text("\n")` 会在它们之间插入换行。
- **解决**：`DROP_TAGS` 增加 `acronym/samp/tt/kbd/var/cite`；
  `strip_noise()` 末尾调用 `soup.smooth()` 合并相邻文本节点。

### 2.8 带标签的字段抓成了整行
- **现象**：详情页分类显示成「作者： 唐家三少」。
- **原因**：`.book_info div` 命中第一个 div（作者行）；而经典模板是「作　　者：xxx」（含全角空格）。
- **解决**：新增 `label_fields` 规则（`{"category": ["类型"], "status": ["状态"]}`），
  按标签定位冒号后的值，且标签内部允许空白（`作\s*者`）。

### 2.9 SSL 证书过期
- **现象**：`SSLCertVerificationError: certificate has expired`。
- **解决**：`HttpSession` 捕获 `SSLError` 后自动降级 `verify=False` 重试一次，
  并屏蔽重复告警（在日志中留痕）。

### 2.10 抓错页面时不能把导航当正文
- **现象**：极端情况下（404 页、验证页）会返回一堆导航文字当"正文"。
- **解决**：加两道闸——正文总字数 `< 20` 直接抛错；
  `looks_like_nav()` 判定"短文本 + 大量导航词"时抛 `ParseError`，
  界面显示「抓到的内容疑似导航/推荐页而非正文，请切换书源或重试」。

## 3. 界面与阅读器

### 3.1 调字号没反应
- **现象**：点 A+/A− 只改了配置，正文没变。
- **原因**：`render(paragraphs=None)` 里有一句「没传段落就 return」，而字号变化时正是没传。
- **解决**：`render()` 缺参时使用内部保存的 `self._paragraphs` 重绘。

### 3.2 换主题后"黑字黑底"
- **现象**：切到夜间主题，背景变暗但文字仍是黑色，几乎看不清。
- **原因**：文字颜色写在 `QTextCharFormat` 里（而不是 CSS），只换样式表不重绘字符格式。
- **解决**：主题切换后强制 `render()` 重绘；设置对话框保存后同样重绘。

### 3.3 滚动位置丢失（三个原因叠加）
- **现象 A**：切章再切回来，回到章首。原因：`set_loading()` 清空视图时把
  `_scroll_pos` 重置为 0，而"记住位置"发生在清空之后。
  → 解决：新增 `remember_position()`，在清空视图**之前**记录。
- **现象 B**：即使记下了位置，恢复后仍在顶部。原因：`setHtml` 后文档尚未完成布局，
  滚动条最大值是 0，`setValue(600)` 被钳制为 0。
  → 解决：`_restore_scroll()` 轮询等待（每 40ms 一次，最多 12 次）直到能容纳目标位置。
- **现象 C**：跳章后回到上一章，位置还是丢。原因：进度表一本书只存一条记录，
  新章节的进度覆盖了旧章节的。
  → 解决：阅读器内维护「章节 URL → 滚动位置」的会话内映射，切章前先存旧章位置。

### 3.4 没加入书架的书不记进度
- **现象**：只是随手读一章，下次打开要重新找章节。
- **解决**：`Library` 增加 `history` 分支，未加入书架的书也记录阅读历史与进度；
  书架页底部增加「最近阅读」区块。

### 3.5 自检脚本误报（不是产品 bug）
- **现象**：断言"字号已应用"失败，但界面其实是对的。
- **原因**：`QTextBlock.charFormat()` 在首块会返回默认格式（黑色、无字号），
  而真实字符格式在文本位置上。
- **解决**：改用 `QTextCursor` 定位到第 1 个字符再读 `charFormat()`。

## 4. 启动与打包

### 4.1 run.bat 在 cmd 里解析失败（已修复）
- **现象**：双击 `run.bat` 输出
  `'�环境并安装依赖' is not recognized as an internal or external command`，
  并且明明 `.venv` 存在却走了"创建虚拟环境"分支，最后报"创建虚拟环境失败"。
- **原因**：我用 **UTF-8 编码 + LF 换行** 保存了批处理文件。
  `cmd.exe` 按当前代码页（中文 Windows 为 GBK）逐行解析，且对 LF 换行的多行
  `if (...)` 块处理异常，导致整段逻辑错乱。
- **解决**：重写为 **ASCII 编码 + CRLF 换行**（实测：49 个 CRLF、0 个裸 LF、
  最大字节值 126），并把中文说明移到 README。现在双击可正常跳过安装直接启动。
- **经验**：`.bat` 永远不要用 UTF-8/无 BOM 保存；跨语言用 ASCII 最稳。

### 4.2 窗口标题重复
- **现象**：标题栏显示「小说搜索阅读器 v1.0.0 - 小说搜索阅读器」。
- **原因**：同时设置了 `setApplicationDisplayName()` 与 `setWindowTitle()`，Qt 会拼接。
- **解决**：去掉 `setApplicationDisplayName`，标题固定为「小说搜索阅读器 v1.0.0」。

### 4.3 单文件 exe 秒退（改为 onedir）
- **现象**：`dist/NovelFound.exe` 启动后 1 秒内进程消失，无任何输出。
- **定位**：用最小 `hello world` 样例做对照实验——**同样失败**，报
  `[PYI-xxxx:ERROR] Could not create temporary directory!`；
  加 `--runtime-tmpdir` 后变成
  `Failed to extract VCRUNTIME140.dll: failed to open target file! fopen: Permission denied`。
  → 证明是环境对"运行时解包到临时目录"的限制，**与应用、与 spec 无关**。
- **解决**：`build/novelfound.spec` 默认改为 **onedir** 模式（不打解包、直接运行），
  实测 2 秒内出窗口；单文件模式保留为开关
  `NOVELFOUND_ONEFILE=1 pyinstaller ...`，并在 README 里注明其前置条件。
- **你的环境**：普通桌面通常两种模式都能用；onedir 启动更快、也更容易过安全软件。

### 4.4 PyInstaller 装不上
- **原因**：同 1.1（pip 写临时目录被拒）。
- **解决**：复用 wheel 直装方式，装了 pyinstaller 6.22.2 +
  pyinstaller-hooks-contrib / altgraph / pefile / pywin32-ctypes / packaging / setuptools。
- **你的环境**：`pip install pyinstaller` 即可；当前 `.venv` 里已经装好，可直接重新打包。

## 4.5 `tempfile.mkstemp` 在受限环境下会卡死（新增）

- **现象**：单元测试跑到 `SourceStats` 那组时**整个进程挂住**，没有任何输出、也不报错；
  单独验证发现 `tempfile.mkstemp(dir=<系统临时目录>)` 调用后不返回。
- **原因**：与 1.1 同源——受限环境对系统临时目录的新建文件操作会阻塞（pip 早期
  「下载超时 120 秒」其实也是这个原因，而不是网速慢）。
- **解决**：新增 `novelfound/storage.py`，用「同目录 + 固定后缀 + 进程号」的临时文件
  配合 `os.replace` 实现原子写入，替换掉 config / library / source_stats 里的
  `mkstemp`；测试的临时目录也改到工作区内（`tests/.tmp/`）。
- **影响面**：普通环境无差别（`mkstemp` 本身没问题），但这一改动让持久化更少依赖
  环境特性，属于净收益。

## 5. 我（助手）的操作失误

### 5.1 误杀了你正在运行的 Anki ⚠️
- **经过**：验证 `run.bat` 时用 `Get-Process pythonw | Stop-Process -Force` 清理测试进程，
  而 Anki 也以 `pythonw.exe` 运行，被一并强制结束。
- **原因**：按**进程名**批量筛选，范围过大。
- **正确做法**：按 PID、命令行或窗口标题精确定位后再结束；
  后续所有验证我都改为「记录启动前后的 PID 差集 + 匹配窗口标题」。
- **影响**：Anki 会持续写盘，强制结束一般只可能丢失最后几秒操作；
  若提示"数据库未正常关闭"，按提示让它自动检查即可。

### 5.2 命令挂起 120 秒
- **经过**：`cmd /c run.bat | Out-Null` 一直不返回，直到超时。
- **原因**：`run.bat` 用 `start` 启动的 GUI 进程**继承了管道句柄**，
  PowerShell 等到管道关闭才算结束。
- **解决**：改用 `Start-Process -PassThru` 拿 PID，不用管道。

### 5.3 PowerShell 单引号里的 `\n` 不是换行
- **经过**：`Set-Content -Value 'import sys\nprint(...)'` 写出的 Python 文件里
  是字面量 `\n`，PyInstaller 打包时直接 `SyntaxError`。
- **解决**：用 here-string 或 `-join "`r`n"` 显式拼 CRLF 再写文件。

## 6. 经验清单

1. **外部站点抓取要假设"随时会变"**：选择器全失效时必须有启发式兜底 + 中文报错，
   而不是白屏或乱码；多源冗余比单源死磕更实用。
2. **广告过滤宁可用白名单保护正文容器**：任何"含 ad 就删"的规则都会误伤
   `content_read` 这类名字。
3. **取文本块不能只按长度**：外层容器永远更长，要按选择器优先级。
4. **目录要按 `<dt>` 分段 + 去重保尾 + 自动翻转**，否则"最新章节"预览块会污染顺序。
5. **颜色/字号写在字符格式里**：改主题或字号后必须重绘文档。
6. **滚动位置恢复要等布局完成**，并区分"同一章重绘"和"换章"。
7. **`.bat` 用 ASCII + CRLF**；中文说明放文档里。
8. **批量结束进程前先按 PID/命令行确认**，不要只按进程名。
9. **打包失败先用 hello world 对照实验**，能立刻区分"环境问题"和"应用问题"。
10. **给打包产物留一条自检通道**（本项目的 `--selftest`），
    windowed exe 没有控制台时，靠退出码 + 报告文件才能确认它真的能联网抓书。

## 8. 本轮新增功能中的问题（首行缩进 / 书源导入）

### 8.1 首行缩进必须按字体度量计算
- **坑**：直接写死 `setTextIndent(40)` 这类像素值，用户放大字号后缩进会显得过小。
- **做法**：用 `QFontMetrics(font).horizontalAdvance("汉") × 缩进字符数`，
  字号/字体一变缩进同步变；并且**不要**往正文里插全角空格（会污染复制与字数统计）。

### 8.2 Legado 书源的 `searchUrl` 选项段解析
- **坑**：形如 `/s.php,{"method":"POST","body":"s={{key}}"}`，用
  `partition(",{")` 切分后选项段**已经丢掉了开头的 `{`**，直接 `json.loads` 会失败，
  结果被当成 GET 请求。
- **做法**：按需补回 `{` 再解析；同时放宽校验——关键词可以出现在 URL 里，
  也可以只出现在 POST 表单里。

### 8.3 导入对话框里的模态弹窗
- **坑**：导入成功后弹 `QMessageBox`，自动化脚本会被永久阻塞（真实用户也要多点一次）。
- **做法**：改成在对话框内的状态标签里显示结果，不打断操作；
  弹窗只保留给"必须用户确认"的场景。

### 8.4 选择器字段要保留兜底链
- **坑**：从 Legado 转换时只取源里的一个选择器，站点小改版就全废。
- **做法**：转换后的字段是「源里的选择器 + 内置兜底选择器」的列表，
  解析器按顺序尝试，命中即用（这也是内置书源一直很稳的原因）。

### 8.5 探测新书源（方案 B）实现中的两个坑
- **重复请求**：如果"每个搜索写法 × 每套模板"都各自抓一次页面，最坏要几百次请求。
  → 改成**每个搜索写法只抓一次**，拿这份 HTML 本地比对所有模板
  （用一个 `_CachedHttp` 把预取页面喂给 `RuleSource`，不改解析器）。
- **URL 合法性校验太松**：`urlparse("https://这不是网址")` 也能得到 netloc，
  导致"输入了中文"这种明显错误被当成正常域名去请求。
  → 加校验：主机名必须匹配 `[A-Za-z0-9.-]+` 且含至少一个点。

### 8.6 测试里的"首页前缀"陷阱
- **坑**：测试用的假 HTTP 按 URL 片段匹配页面，而 `https://site.com/` 是**所有**
  该站 URL 的前缀，于是所有请求都返回了首页，测试假阳性/假阴性。
- **做法**：假 HTTP 改成按「路径 + 查询串」匹配（首页只在 path 为 `/` 时返回），
  这样 `?searchkey=`、`/book/27/index.html` 各走各的。

### 8.7 网络找书源（方案 C）踩的三个坑
- **搜索引擎大面积不可用**：实测百度/360/搜狗/DDG/Startpage/Yandex 全被反爬或需要 JS，
  只有 Bing（cn.bing.com / www.bing.com）能返回可解析的 HTML。
  → 引擎做成可扩展清单，默认只留 Bing；失败时明确提示而不是静默无结果。
- **搜索词决定成败**：`"书名 小说 在线阅读"` 出来的几乎全是起点/云起/百科等官方站
  （8 个候选里 6 个要过滤），而 `"书名 笔趣阁"` 直接给出 7 个可用聚合站。
  → 改成三个搜索词合并去重（笔趣阁 / 免费小说 / 在线阅读），并给"标题含笔趣阁"
  的候选加分。
- **"能搜到"不等于"搜索有效"**：有的站搜索接口失效，任何关键词都返回同一批书，
  探测（搜索→目录→正文）会**全部通过**，存下来却是个假书源。
  → 探测第 2 关增加**关键词相关性校验**：搜索结果里必须出现与目标书名匹配的条目，
  否则判定"搜索接口已失效"。这一条同时修好了方案 B 的误判。
- **站点自己的搜索表单最靠谱**：有的站搜索参数是 `?key=`、表单无 action（提交到当前页），
  硬编码的写法覆盖不到。
  → 探测时先解析首页 `<form>`（action + method + 文本输入框 name）生成搜索写法，
  优先尝试，再退回通用清单。

## 9. 线上崩溃复盘：点「网络找书源 → 开始查找」程序直接消失

这是本项目最严重的一个 bug（用户实际遇到），记录完整排查过程。

### 现象
在「网络找书源」对话框里填好书名、点「开始查找」，**程序窗口瞬间消失**，
没有任何提示（打包后的 exe 是 `console=False`，什么都看不到）。

### 定位过程
1. **先怀疑输入**：用离屏 + 真实窗口跑了 3 种输入、4 种操作时序、8 种奇怪输入，
   全部正常 → 说明不是输入问题。
2. **翻 Windows 事件日志**（关键一步）：

   ```
   故障应用程序名: NovelFound.exe
   故障模块名称:   Qt5Core.dll 5.15.2.0
   异常代码:       0xc0000409
   异常数据:       0000000000000007
   ```
   `0xc0000409` + 子码 `7` = `FAST_FAIL_FATAL_APP_EXIT`，即 `abort()`；
   故障模块是 Qt5Core.dll（`qFatal()` 所在库）——这正是
   **"PyQt 槽函数里抛出未捕获 Python 异常"** 的典型签名：
   PyQt5 打印 traceback 后调用 `qFatal()` → `abort()` → 进程消失。
3. **从用户处拿到关键信息**："是在网络找书源里点开始查找崩的"，
   而我的自检脚本只调用了对话框的内部方法、**没点按钮**，所以完全没覆盖到。
4. 直接点按钮复现，抛出：

   ```
   AttributeError: 'str' object has no attribute 'base_url'
     File ".../ui/source_discover_dialog.py", line 121, in on_start
       existing = [s.base_url for s in self._existing_hosts()]
   ```

### 根因
`_existing_hosts()` 返回的是**域名字符串列表**（`["www.hetushu.com", ...]`），
而 `on_start()` 里却按对象取 `s.base_url`。异常发生在 Qt 的 `clicked` 槽里，
于是走 `qFatal()` → 整个进程被 abort。

### 修复
1. 一行修正：`existing = self._existing_hosts()`；
2. 新增 `novelfound/errors.py`：
   - `install_crash_handler()`：`sys.excepthook` + `threading.excepthook` 把 traceback
     写入数据目录的 `crash.log`，并用 `faulthandler` 覆盖原生崩溃；
   - `guard_slot` 装饰器：给按钮槽套一层保护，出错时**记日志 + 界面提示**而不是崩掉
     （已用于导入/探测/发现/订阅等入口按钮）；
   - 注意：PyQt 会把 `clicked(bool)` 的参数传进槽，装饰器必须按原函数签名裁剪参数，
     否则会 `TypeError`（这个坑当场踩到并修掉了）。
3. 把内部进度标记 `__elapsed__` 改成独立信号 `elapsed(float)`，
   不再混进对话框日志。

### 教训
- **测试要点按钮，不要只调内部方法**：这次自检覆盖了"结果处理"，漏掉了"点击入口"，
  于是最常被用户触发的路径反而没有回归测试。现在 `tests/verify_ui.py` 会真的
  `button.click()` 跑一遍导入/探测/发现三条路径。
- **窗口化程序必须有崩溃日志**：没有 `crash.log` 时，这类崩溃对用户就是"程序没了"。
- **Windows 事件日志 + WER 报告是定位崩溃的最快线索**（异常代码能区分
  "Python 异常被 qFatal" 和 "原生访问越界"）。

## 10. 第二轮反馈修的三个问题

### 10.1 「继续阅读」总是跳到第一章
- **现象**：从书架点进一本书，按钮显示「继续阅读」，点下去却总是第一章。
- **原因**：`_fill_catalog()` 只给"上次读到的那一章"加了 `▶` 标记并滚动过去，
  **没有调用 `setCurrentItem()`**；于是 `catalog.currentRow()` 是 `-1`，
  而 `_on_read_clicked()` 写的是 `index = current if current >= 0 else 0` → 回落到 0。
- **修复**：填充目录时把进度那一章设为当前行；点击时若没有选中行则用记住的
  `progress.index`，不再硬编码 0。
- **验证**：两个独立进程跑完整流程——进程 A 读第 4 章并滚动到 500px 后关闭，
  进程 B 重新打开 → 书架 → 「继续阅读」→ 落在第 4 章且滚动位置恢复到 500px。
- **教训**：进度"存了"和"用上了"是两件事，UI 的选中状态也要跟着恢复。

### 10.2 阅读时左侧栏碍眼
- 顶栏加「☰ 侧栏」按钮 + `Ctrl+B`；进入阅读器自动收起、返回目录自动恢复；
  状态写进配置（`sidebar_visible`），下次启动保持；设置里可关闭自动隐藏。
- 实现要点：隐藏用 `setVisible(False)`（比把分隔条拖到 0 更好恢复），
  重新显示时用 `QTimer.singleShot(0, ...)` 恢复原宽度。

### 10.3 经常被"拒绝访问"（403/429）
分两类原因，对应不同解法：

| 原因 | 解法（本次已做） |
| --- | --- |
| 请求头太"素"，被站点一眼认出是脚本 | 补齐 `Sec-Fetch-*`、`sec-ch-ua*`、`Upgrade-Insecure-Requests` 等；图片请求单独用 `Sec-Fetch-Dest: image`；带 Referer 时把 `Sec-Fetch-Site` 切成 `same-origin` |
| 同一站点被瞬间打太多次（尤其封面） | ① 按站点排队限速（`_reserve_slot` 在锁内预约时刻、锁外 sleep，同站串行、异站互不阻塞，间隔带 ±35% 抖动）；② 封面改成**只在卡片可见时下载 + 并发上限**（默认 2），失败不重试 |

> 还有一类是真正的人机验证（Cloudflare 等），纯 HTTP 抓取过不去；
> 文档里讨论过"无头浏览器 + Cookie 桥接"的方案，暂未实施（体积与合规代价）。

## 11. 双页分栏的三个坑（第三轮反馈）

### 11.1 分页高度没扣文档边距 → 每页最后一段被裁掉
- **现象**：双页模式下左右两栏底部都露出半截文字，两栏内容"接不上"。
- **原因**：分页时用 `viewport.height() - 4` 当可用高度，但正文用的是
  `document().setDocumentMargin(26)`，上下各占 26px——实际可画高度只有
  `viewport - 52`，于是每页多塞了约 50px 的内容。
- **修复**：改用文档坐标判断——`blockBoundingRect().bottom() > viewport - margin`
  就从这一段开始新页（含段后间距一起判断，放不下就整体留到下一页，符合阅读习惯）。
- **验证**：遍历所有页，断言 `document().size().height() <= viewport().height() + 2`，
  当前 0 页超标（修复前是每页都超标）。

### 11.2 滚轮在正文上只滚动单栏
- **原因**：`QTextBrowser` 是 `QAbstractScrollArea`，wheel 事件先被它消费，
  根本传不到 `ReaderView.wheelEvent`。
- **修复**：在事件过滤器里拦截两栏 viewport 的 `QEvent.Wheel`：
  翻页模式下统一整屏翻页；仅当"某段比整页还高、该页确实需要页内滚动"时才放行。

### 11.3 双页时每栏太窄
- **原因**：早期实现是"总宽固定为 content_width，两栏平分"，
  结果 820px 的窗口每栏只有 378px，一行放不下几个字。
- **修复**：**每栏按单页宽度**取 `min(content_width, (可用宽 - 栏距) / 2)`——
  宽屏上两栏都是 820，窗口不够宽才等比缩小。

> 附带：正文上方新增**常驻章节标题**，解决"跳章时只有一瞬间空白、不知道当前是哪一章"。

### 11.4 修 11.1 时又踩了一个坑：分页用了绝对坐标
- **现象**：修完 11.1 后，每章只有第一页装满文字，**后续每页只剩一段**。
- **原因**：`rect.bottom() > viewport - margin` 里的 `rect` 是**文档绝对坐标**，
  于是第一页之后每个段落的底部都超过阈值 → 每段都被判成"放不下" → 一段一页。
- **正确做法**：要和"本页第一段的顶部"比较：
  `rect.bottom() - page_top > viewport - 2*margin`，换页时把 `page_top` 更新为新页首段顶部。
- **教训**：涉及坐标的判断，先想清楚是"绝对坐标"还是"相对当前页的偏移"。

### 11.5 章节标题栏挡住了鼠标 → 顶部浮条唤不出来
- **原因**：鼠标移到窗口顶部时，光标其实落在**章节标题栏**（或画布空白）上，
  而不是正文视图的 viewport 上；事件过滤器只装在 viewport 上，所以收不到 MouseMove。
- **修复**：给 `canvas`、`page`、`chapter_header` 也开 `setMouseTracking(True)` 并装过滤器，
  任意位置移动都能唤出浮条。

### 11.6 章首标题（新增功能）
- 每章正文开头加一段**大字号居中标题**（字号 = 正文字号 + 4，加粗，段后留白），
  只在章节第一页出现；`_render_into(..., heading_first=True)` 控制样式。
- 注意：标题作为第 0 段进入段落列表，所以 `block_index` 语义整体后移一位——
  旧进度会落在标题那一段（无害）。

### 11.7 行级分页：`QTextLine.height()` 不是行步进（第四轮反馈，最关键的一个）

- **现象**：双页模式下仍有约三分之一的页底部被裁掉（自检实测 33 页里 10 页超标，
  `doc_h=817` 而 `viewport=812`），偶尔还会因为"某段太高"冒出页内滚动条。
- **根因**：段落格式用了 `setLineHeight(line_height * 100, ProportionalHeight)`
  （默认 190%）。此时 `QTextLine.height()` 返回的只是**文字本身**的高度，
  行与行之间真正的步进是 `height × 行距倍数`：正文 30 × 1.9 = **57**，
  章首标题 37 × 1.9 = **70.3**。原分页代码按 `line_top + line.height()` 累加，
  一页就多塞了 2~3 行（实测每行少算 27px），底部自然被裁掉。
- **实测模型**（离屏打印每一行/每一块的坐标得出，误差 0）：
  - 行步进 = 相邻行的 `y` 之差；最后一行 = 下一块顶部 − 本块顶部 − 本块下间距。
  - 文档高度 = 最后一行底部（含步进）+ **一个** `documentMargin`；
    最后一块自己的下间距**不计入**文档高度。
  - 一页可用高度 = `viewport - 2 × documentMargin`，判断用
    `行底部(含步进) - 页顶 ≤ 可用高度`。
- **修复**：新增 `_line_advance()`（相邻行 y 差 / 用块占位反推最后一行）与
  `_block_span()`（下一块顶部 − 本块顶部 − 下间距），分页改用真实步进累加。
- **验证**：33 页 0 溢出；页面填充率 min 0.917 / avg 0.963（不浪费版面）；
  自检新增"所有页均不溢出（行级分页）"和"每页都装满（不是只塞一行）"两条结构性断言，
  界面自检 136/136、单元测试 66/66 通过。
- **教训**：凡是"按高度分页"，先确认拿到的 height 是**内容高度**还是**行步进**；
  比例行距下两者差一倍。

## 13. UI 重构 P1（信息架构）踩的坑

### 13.1 浮层不能进布局
- **背景**：搜索面板 / 目录抽屉 / 遮罩要"盖"在页面上。
- **做法**：它们都是 `centralWidget()` 的子控件，**不加入任何布局**，
  由 `MainWindow._layout_overlays()` 在 `resizeEvent` 与打开时统一 `setGeometry()`。
- **坑**：一开始想把抽屉塞进 `QSplitter`，结果 `setSizes` 与动画互相打架；
  方案里已经预判到（见风险表），照做即可。
- **顺序**：遮罩 → 浮层 → 轻提示依次 `raise_()`，否则遮罩会盖住面板。

### 13.2 「继续阅读」差点因为目录改抽屉而回退
- 旧实现靠 `catalog.currentRow()`（"目录里选中了哪一行"）决定跳哪一章，
  目录一旦搬进抽屉、详情页不再常驻列表，这个值就没有意义了。
- **新做法**：`BookView.reading_index()` 只认 `_progress_index`（上次读到的章节序号），
  抽屉里的 ▶ 高亮纯属展示。自检里那条回归断言（点「继续阅读」打开的是上次那一章）
  **原样保留**，并额外断言 `reading_index()` 的数值。

### 13.3 简介"默认 3 行"不能用 `sizeHint()`
- **现象**：`intro_label.sizeHint().height()` 在标签被限高之后返回的是**限高后**的高度，
  于是"要不要显示展开按钮"永远判成不需要。
- **修复**：用 `QFontMetrics.boundingRect(QRect(0, 0, 宽度, 10000), TextWordWrap, 文本)`
  量一次全文高度，再和 `lineSpacing × 3` 比。自检断言"简介默认限高 3 行"。

### 13.4 封面节流在"不可见页面"里会停住
- `_pump_cover_queue()` 只处理**可见**的卡片，这是为了省流量；
  但书架首页刚启动时如果还没显示，队列就空转。
- **修复**：`show_library()`、`open_search_palette()` 里各 `start()` 一次节流定时器，
  等控件真正可见后再消费队列。

### 13.5 废弃配置键要主动清理
- `sidebar_visible` / `auto_hide_sidebar` / `splitter_sizes` 不再使用，
  但老用户的 `config.json` 里还在。`AppConfig.load()` 现在会把这些键
  **读出来就丢掉**（`DEPRECATED_KEYS`），避免残留值被别处误读。

### 13.6 自检断言迁移策略
- 方案第 7 节要求"不要删断言，只改断言对象"。实际按映射表逐条改写：
  侧栏 → 抽屉、搜索框 → 浮层输入框、卡片 → 结果行、书架卡片 → 网格格子。
- 结果：自检 **136 → 162 条**，全部通过；单元测试仍是 **66 条**全通过
  （本轮只动界面层，抓取逻辑零改动）。
