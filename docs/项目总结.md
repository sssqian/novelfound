# NovelFound 项目总结

> PC 端小说搜索与阅读器（Python 3.13 + PyQt5 5.15，Windows / macOS / Linux）
> 仓库：`D:\AI\option\novelfound`　｜　本文截至 **2026-09-11**，数字均为实测

---

## 1. 这是什么

一个"笔趣阁风格"的桌面应用：**输入书名 → 多书源并发搜索 → 卡片式结果 → 简介与完整目录 → 应用内直接阅读**，
全程过滤广告与无关链接，只留纯净正文。可打包成免安装的 Windows exe。

| 用户可见能力 | 说明 |
| --- | --- |
| 多书源搜索 | `Ctrl+K` 搜索浮层，300ms 防抖，并发查询所有启用书源；单源失败不影响其它源 |
| 书籍详情 | 封面 + 元信息 + 简介（3 行可展开）+ **单一主按钮**（开始 / 继续阅读） |
| 目录抽屉 | 左侧滑出（250ms），章节筛选 + 当前章 ▶ 高亮 + 点击跳转 |
| 内置阅读器 | 纯文本渲染，不加载原站脚本/图片；居中限宽 820px；**单页 / 左右双页**；滚动 / 整页翻页 |
| 阅读设置浮层 | 右上角 `Aa`：字号 / 字体 / 行距 / 段距 / 缩进 / 页宽 / 主题 / 翻页方式，**改完即时生效** |
| 书架首页 | 启动首屏，封面网格（书名 + 百分比 + 封面右下角角标），点击进详情 |
| 本地导入 | 导入 **TXT / EPUB**（按钮或拖进窗口）→ 编码识别、自动切章、**分卷折叠**、EPUB 取 spine/NCX/封面/**正文插图**，另有「本书插图」浏览（含正文没引用的图）→ 进书架即可阅读，也可被搜索到 |
| 浏览历史 | 右上角 `🕘`（`Ctrl+H`）：**一本书只留一条**记录（按书去重），记录在离开阅读器或关闭应用时写入；点一条回到那本书、那一章；上限 30 条 |
| 广告屏蔽 | DOM 层删广告位 + 文本层正则过滤；可开严格模式剔除纯英文推广行与正文内链接 |
| 书源生态 | 内置 4 源；支持导入本项目规则 JSON 与 **Legado 书源**；**域名一键探测**；**搜索引擎找新站**；成功率评分与连续失败自动禁用 |
| 容错与限流 | 超时重试 / 编码自动识别 / SSL 降级 / 同站限速 / 封面懒加载 + 并发上限；中文友好报错 |

| 17 | 4 处体验调整 | ① `Aa` 浮层点正文即收起；② 阅读时**删掉顶部应用栏**（真沉浸）；③ 历史改为**一本书一条**、只在结束阅读/关应用时写；④ 历史上限 500 → **30** |

### 最硬的一个 bug（第 10 轮）

双页模式下约 1/3 的页底部被裁，**连续修错两轮**：

1. 第一轮猜"没扣文档边距" → 改用文档坐标判断 → 仍溢出；
2. 第二轮猜"用了绝对坐标" → 改成相对页顶比较 → 变成"一段一页"，更糟；
3. 第三轮放弃猜测，**离屏打印每一行/每一块的坐标**，才发现根因：

> 段落用了比例行距（190%），此时 `QTextLine.height()` 只是**文字本身**的高度（30px），
> 行与行之间的真实步进是 `height × 行距倍数` = **57px**。按 `height()` 累加，每行少算 27px，
> 一页就多塞 2~3 行。

改用真实步进后：33 页 **0 溢出**，填充率 min 0.917 / avg 0.963，超长段落正确拆到 19 页。
**教训**：涉及测量的问题，猜两轮就该去打印真实数据。

## 7. 关键设计决策（含被否决的方案）

| 决策 | 为什么 | 被否决的替代 |
| --- | --- | --- |
| 书源"规则驱动"（JSON 模板 + 启发式） | 加同模板站点只需一条配置，界面内即可加 | 每站写一个适配类 |
| **不执行书源里的 JS** | 安全边界：只接受 URL 模板与 CSS 选择器这种**数据** | 兼容 Legado 的 JS 规则（改为标记不可用） |
| 阅读位置用**字符偏移** `char_offset` | 跨字号、跨单双页、跨窗口尺寸都稳定 | 像素滚动位置 / 段落序号（都会漂） |
| 分页按**行**而不是按段落 | 长段落要么撑破页面、要么独占一页 | 段落整段不切断 |
| 双页每栏按"单页宽度"取 | 宽屏上两栏都是完整阅读宽度 | 总宽平分（每栏只剩 378px） |
| 浮层**不参与布局**（子控件 + `setGeometry`） | 进布局后动画与布局互相打架 | 塞进 `QSplitter` / 布局 |
| 动画只做视觉，**状态由 `_shown_state` 立刻更新** | 否则"刚关闭、动画还在跑"的 200ms 里状态是错的 | 用 `isVisible()` 当状态 |
| 打包用 **onedir** | onefile 在受限环境连 Hello World 都失败 | onefile 单文件 |
| 阅读设置**只有一个入口**（`Aa` 浮层） | 曾经设置对话框与阅读器工具栏各有一份，用户改了 A 以为 B 也变 | 两处都留 |
| 浏览历史与书架**分两个 store** | 一个管"读到哪"（实时写），一个管"看过哪些书"（离开阅读器时写），写入时机与去重规则完全不同 | 混在一份 JSON 里 |
| 首页只有书架网格 | 用户明确要求，续读入口收敛到详情页主按钮 | 继续阅读大卡 + 最近阅读横排 |

## 10. 一句话回顾

从"能搜能读"到"读得舒服"，这个项目最大的成本不在功能，而在**两件事**：
一是**测量类问题的试错**（Qt 排版模型花了整整一轮才逼出来），
二是**信息架构的反复收敛**（四轮 UI 重构，最后砍掉常驻侧栏与首页两个栏目）。

两件事的共同解法都是同一个：**把猜变成量、把重复变成脚本、把教训写成文档**——
前两条进了项目 skill，第三条就是 `docs/TROUBLESHOOTING.md`。
